# FOCUS 可配置 Backend 与 ACP 接入规格

Status: 实现完成，第二个 ACP CLI 真机验收待完成

## Problem Statement

读者已经在本机安装并登录了 AI 工具，却只能从 FOCUS 写死的两个 Backend 中选择。一次连接检查可能安装软件，能回复测试文本的模型也可能读不到讨论绑定的原文。维护者每增加一种接法，就要同时修改 Host、设置页、环境配置和探测逻辑。升级时，已有用户还需要继续使用原来的讨论、模型偏好和认证方式。

## Solution

工作台从注册表列出 Backend。用户可以跳过 AI 配置直接打开知识库，等需要 AI 时选择本机程序。FOCUS 用临时来源验证所选模型能读回一段原文，再把真实文章和问题交给它。通过检测的 Backend 供整个 Host 共用。FOCUS 持有讨论、阅读位置、工具权限和知识库写入权，外部运行时负责执行当前一轮。

## User Stories

1. 作为首次打开工作台的读者，我希望直接进入知识库，以便在没有 AI 工具时也能导入并阅读文章。
2. 作为读者，我希望扫描本机时只发现程序路径，以便自己决定何时安装、登录及发起模型请求。
3. 作为读者，我希望只有一个候选时可预选、多个候选时自行选择、没有候选时看到安装指引，以便在首次使用 AI 前确认执行者。
4. 作为读者，我希望每个 CLI 默认只出现一项，显式添加的第二种接法单独命名，以便知道自己检查的是哪条配置。
5. 作为自定义 CLI 用户，我希望添加一份 Manifest 后能手动重新扫描，以便使用新条目而无需中断当前任务。
6. 作为配置维护者，我希望看到错误文件名和原因，以便修复一项配置的同时继续使用其他有效条目。
7. 作为多套 Host 的使用者，我希望每份设置自然找到同目录的预置扩展，并允许指定其他目录，以便隔离测试环境。
8. 作为脚本使用者，我希望启动参数能覆盖环境变量及保存值，以便临时选择 Backend 而不改写平时的偏好。
9. 作为读者，我希望指定程序启动失败时知道是哪一项失败，以免文章被发给另一家 Backend。
10. 作为读者，我希望按实际程序和模型验证读取原文的能力，以便从一个检测结果判断配置能否使用。
11. 作为读者，我希望首次发送时先显示检测状态，通过后自动继续，以便只发送一次；失败时仍能找回输入。
12. 作为读者，我希望保存时复用匹配的检测回执，以便避免重复推理，同时让实际执行参数变化后的配置重新受检。
13. 作为使用多个浏览器页面的读者，我希望各页面看到同一个生效配置，以便保存、发问和切换不会彼此抢占。
14. 作为读者，我希望切换 Backend 后继续同一篇来源的讨论，以便保留历史、阅读位置、笔记和已有证据。
15. 作为读者，我希望每轮都从 FOCUS 提供的上下文开始，以便外部工具先前的原生会话不会改变当前讨论的依据。
16. 作为读者，我希望能取消任务并在请求过期后看到旧按钮失效，以便知道一次确认是否仍然有效。
17. 作为 Codex 用户，我希望升级后沿用原有程序、模型和主动登录入口，以便继续使用已有 ChatGPT 登录态。
18. 作为 DeepSeek 用户，我希望保留原选择、模型偏好和凭据文件路径，以便切换到 dsh 后无须重新录入密钥。
19. 作为读者，我希望设置页按 Backend 提供模型发现、手动模型输入和登录指引，以便配置本机实际支持的选项。
20. 作为候选文档检查者，我希望显式检查经当前 Backend 执行并返回可验证的结构化结果，以便识别检查失败与图片未观察的情况。
21. 作为集成维护者，我希望兼容的 ACP 工具可通过配置接入，以便扩展执行选项时复用现有阅读功能和审批规则。
22. 作为发布维护者，我希望逐项看到真机平台、版本、往返结果、取消清理结果及耗时，以便区分已验证接法与尚未实测的预置。

## Implementation Decisions

- **公开契约（Q1、Q20）**。Backend 是一条可独立检查、选择和应用的配置。设置、HTTP 和前端沿用开放字符串 `backend` 与描述列表 `backends`，保留现有 reader 配置与设置路由。CLI 使用 `--backend`、`--backend-bin`、`--backends-dir` 和已有模型选项。Harness、Driver 属于内部术语。更新随附启动脚本。
- **注册与发现（Q2、Q16、Q17、Q21、Q24）**。内置 ID 固定为 `codex`、`deepseek`、`agy`、`cursor`；Claude Code 和 Codex ACP 由用户注册独立 ID。显式目录优先，否则加载实际设置文件同级的 `backends/`。启动或手动重新扫描只读取 Manifest 和发现可执行路径。保留内置 ID，报告重复或无效文件，隔离失败项。扫描不激活配置、不启动运行时；当前配置及在途任务继续使用原选择。
- **配置解析（Q7）**。命令行优先于环境变量，环境变量优先于保存值。显式启动选择即本进程的确认，跨工作区有效；仅主动保存并应用才持久化。失败时仍可打开知识库，显示指定 Backend 的原因。首次发现路径遵循零、一、多个候选的交互规则，禁止自动安装和静默回退。
- **Manifest 与驱动**。声明 ID、名称、驱动、命令和有序参数、默认模型、环境与能力。路径覆盖只替换可执行程序。注册表按驱动类型创建实例；Host 服务、配置校验、环境准备和设置页均走通用接口。模型目录可选，保留手动输入；发现失败可重试。目录中的某个模型能否执行以该模型的检测为准。
- **准入探针（Q3、Q5、Q9、Q23）**。每次探针创建临时来源和随机标记，仅开放现有 `focus` 工具的 `read_range` 动作。标记仅由该动作返回。Host 同时观测到读取成功与最终回复带回正确标记才签发通过回执。纯文本 CLI 在配置阶段被拦截。首次使用未验证配置时显示「正在检测 Backend」，通过后自动继续原请求；失败时保留输入并给出原因。在通过前用户文章与问题均不发往候选 Backend。
- **回执与应用（Q6、Q10）**。回执身份严格取 Backend ID、解析后的可执行路径、实际模型、最终有序命令参数。保存并应用时，匹配成功记录可复用，其余先探测；旧文本回执自然视为未验证。普通检测不激活。保存并应用从探测前至提交或失败独占切换权；前台任务运行时拒绝切换，仅有后台预生成摘要时取消并丢弃迟到结果。切换期间允许浏览，新 AI 任务及并发应用收到可重试提示。探测或持久化失败保留原保存值和生效值，各页面同步成功结果。
- **迁移与凭据（Q4、Q8、Q11、Q12、Q22）**。Codex 用标准 Manifest 注册已有 App Server 驱动，保留标识、路径、模型、共享登录态及主动发起和取消登录，继续隔离与该登录方式冲突的 API key。DeepSeek 沿用 ID 和模型偏好，重新发现 dsh 并使用其 ACP profile；旧 SDK 专用路径不继承。显式凭据文件仅按 Manifest 声明的变量名向子进程注入，缺文件或缺键时给出修正指引。配置、Manifest 和回执只保存必要路径或名称，避免记录密钥值。其他 Backend 按声明提供外部登录指引。
- **协议与权限**。复用标准库 stdio JSON-RPC 传输，保持统一 Backend 事件词表。ACP 驱动完成握手、创建会话、配置模型及发送提示，映射流式或仅最终提交的消息、活动、权限请求与终态事件。业务工具复用 Host 的本地 MCP 工具桥；协商 HTTP MCP 或经 stdio 代理访问同一工具桥。按执行目的限制工具范围，审批与业务写入由 Host/Core 裁决。
- **讨论生命周期（Q13–Q15）**。每轮启动独立进程和全新原生会话，由 FOCUS 注入来源、近期消息和已存摘要。取消时终止在途执行，结束时关闭工具桥、释放句柄、清理临时环境并回收进程。外部运行时拥有原生日志。超时或断开立即作废待确认请求，禁用旧按钮，提示「本次请求已过期，请重试」。手动重试在同一讨论开启新一轮，涉及授权时重新询问。
- **候选检查（Q19）**。独立检查器经当前 Backend 在只读、无业务工具、有时间限制的环境执行，Host 校验结构化结果；图片能力缺失时记录未观察及原因。默认导入始终只调用解析器。

## Testing Decisions

主验收入口沿用正式工作台与 Host。通过设置页、公开 HTTP 操作、启动参数、讨论结果和可观察到的外部进程行为断言结果。独立候选检查器从其现有显式入口测试。协议替身适合稳定重现失败、并发和迟到事件；真机覆盖另行记录。

| 场景 | 可观察的通过条件 |
|---|---|
| 发现与启动 | 空环境可导入；一个候选可预选，多个供选。扫描没有启动 CLI。验证实际设置文件的相邻目录及显式覆盖、四个内置 ID、有效与坏文件混合、内置 ID 冲突、重新扫描期间任务继续。启动覆盖跨工作区生效；重启可读回原保存值。 |
| 探针及首个请求 | 用替身分别返回纯文本、错误标记、成功工具调用但无正确最终回复，以及完整往返；只有最后一项通过。核对请求顺序与负载：失败时没有文章和问题，通过后原请求执行一次。依次改变回执四个字段，验证失效、复用和旧回执行为。 |
| 应用与并发 | 从两个页面发问、检查及保存。覆盖前台忙碌、后台摘要迟到、探针失败、写盘失败和第二次应用；观察输入、有效配置、保存值、讨论与 Cursor 均符合契约。 |
| 讨论与协议 | 同一来源连续两轮及跨 Backend 后延续 FOCUS 讨论；验证全新会话、分块与最终消息、工具权限、HTTP 与 stdio MCP 接入、正常退出、取消和断开。过期确认无法提交；重试须重新确认。检查进程及临时资源回收。 |
| 迁移与摄入 | 已有 Codex 的登录、取消登录、程序和模型配置可用；DeepSeek 使用 dsh 并按声明注入凭据，缺失项能定位。普通导入零模型请求。显式检查覆盖有效结果、结构不符、无图、图片能力缺失、超时和取消。 |
| 真机发布验收（Q18） | dsh 必测，另选 agy 或 Cursor CLI。两者经同一 ACP 驱动完成阅读讨论、真实源文读取往返、取消及资源释放。DSH 通过后直接下线 SDK。默认 Codex 单独跑 App Server 兼容回归。逐项记录平台、CLI 版本、启动至握手完成和发问至首段输出的时间、失败及未覆盖项；未经真机验证的预置标为「未实测」。 |

沿用现有 Backend 设置浏览器流程、Stage 6B 配置与工作流测试、Backend onboarding、讨论工具范围和候选检查器测试。将旧断言中的默认 Codex、自动安装、无工具文本探针和无效配置可应用替换成新契约。保留原有失败回滚、来源绑定和已停止任务不得迟到提交的回归覆盖。

## Out of Scope

纯文本 CLI 兜底、通用 CLI 参数映射语言、内置 Claude 或 Codex ACP 条目、原生会话恢复、进程池、文件监听、自动拆轮续跑、在途热切换、应用内下载及升级运行时、DSH 专属归档与启动重试、双 DSH 路径、默认导入触发 AI，以及容器沙箱、多租户与工作流编排。
