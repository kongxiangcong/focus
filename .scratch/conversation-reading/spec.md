# 统一阅读与对话：需求规格

Status: needs-triage
日期：2026-11-15
阶段：方案与交互原型，待用户体验后决定是否实施。本文不是已交付功能声明。

## 1. 目标与边界

将精读与文章对话合并为唯一「阅读」工作区：左侧连续完整原文，右侧绑定本篇来源的持续讨论。首次打开自动联合生成中文骨架和一段导读；每轮回答中的原文依据可在左侧准确定位、临时高亮并显示关联浮卡。用户自由提问、跨章节阅读、追问与继续讲解，不需要先选学习模式或逐段解锁。

本次交付为本规格、实施计划、逐项工单、隔离且可交互的原型。真实模型、联网、数据迁移和正式阅读界面改造须在用户确认原型并决定开发后执行。原型使用完整的合成短文与预设回答，界面注明演示属性，不触碰知识库，不将模拟引用校验当作生产证据。

首版生产范围：入口收敛、全文渲染、联合开场、文章持续对话、句子/段落/图表/公式证据、外部来源标识、选文提问、恢复现场、原有笔记兼容、浅深主题与响应式。

不在首版：知识掌握评分、课程和强制测验、多篇论文自动综合、音频播客制作、PDF 像素级框选证据、跨译文精确映射、自动把回答保存成笔记。PDF 原件可打开查看，精确联动首先针对 Parser Bundle 的排版原文。

## 3. 用户路径与入口

R01 知识库只保留一个阅读主操作。首次「阅读」，恢复「继续阅读」，完成后仍可「阅读」。解析异常保留查看问题/重试解析，不用假进度遮盖。

R02 打开已解析来源立即显示原文，并打开/恢复该 Source 的 FOCUS Discussion。原文读取、联合开场、对话是独立状态；其中一个失败不得清空另外两个。

R03 首次开场由中文层级骨架与一段连贯中文导读构成；不要求「生成」「进入正文」操作。默认 4–7 个主要节点，可因实际文章结构调整；不硬凑章节。每个节点链接对应原文范围。导读建议 200–400 字、最多 500 非空白字符、一个自然段；讲清问题、方法、证据边界，不复制摘要或保证成果。

R04 一次候选调用返回 `{structure, guide}`；同一批原文、同一版本、联合校验后原子发布。失败最多两次整体修复，不能前端截字；成功的旧资产在替换成功前保留。并发请求合并，不每次打开重算。已有 v1 骨架与导读可校验复用，不需重新调用模型。

R05 入库发布后可预准备开场（服从现有后台处理设置）；旧来源首次打开自动补齐。用户可停止自动准备；停止后此次打开不循环重启，只在显式重试/下次明确打开时按策略处理。模型不可用时原文可读，开场和输入区分别说明配置问题。

R06 正常自由对话，不展示预设首问建议或固定下一步按钮；「继续」作为用户自行输入的普通问题沿讨论脉络推进，允许换问题、回看、深入。不要自动出题或每轮强行追问。

R07 长文上下文含本篇身份、版本、骨架、历史摘要、近期消息和选文；模型可检索/读取本篇任何范围。不能把摘要当全文；有限上下文时明确不足，不能假称通读全文。

R08 选文后「问这段」写入带版本的引用条，用户可移除；草稿绑定当时引用，不随滚动自动变化。跨块选文拆为多个有序范围。原文中的指令只作文章内容，不能更改系统规则。

R09 必要时调用后端已有 web 能力；不可用时明确说明。回答区分原文、外部资料、解释/推断；无证据的模型常识不能自动标成「联网」。链接需实际工具结果，不编造网页。

R10 回来时恢复对话、草稿、原文手动阅读位置、选中回答；不重复开场。首次开场不重复写进模型消息历史，作为版本化背景资产引用。若用户已发送问题，迟到的开场填回顶部原位置，不插入最新回答。

## 4. 布局、排版与现有能力

### 4.1 桌面

阅读工作区（不含应用导航）宽 ≥ 960px：两栏，默认 60/40；原文最小 480px，对话最小 340px，中缝命中宽 8px。拖动即时调整不播放宽度动画，记住比例；键盘方向键每次 2%，Home 恢复 60/40，暴露 separator 的值和方向。

页头仅返回、来源标题、目录、笔记、更多；不叠加专用模式选择。两栏各自一条轻工具行和独立滚动容器。原文内容测量宽度建议 680–760px，随用户字体/行宽偏好限制，不沿用旧单栏 1040px 当双栏正文宽度。

原文标题 28–32px/1.3，正文沿用所选阅读字体（默认思源宋体）18px/1.86，章节 23px/1.4；回答 UI 无衬线 15px/1.8；元信息 12–13px。公式、代码、宽表在自身容器横向滚动，整页不得溢出。图表在原文位置展开，有图注与放大操作。

右侧开场直接显示骨架与一段导读，骨架/导读没有独立生成按钮。开始讨论后仍留在顶部，可折叠；目录始终可找回。用户提问用现有浅底气泡；模型回答直接落在画布上，不每条包重卡片。输入框沿用 ghost 工具和行内发送，圆角与焦点环取现有 token。

2026-11-15 用户评审修订：界面不添加宣传式标题、引导语、辅助口号或解释性小字，包括「让数据更靠近计算」「先有全貌，再慢慢读懂」「本篇原文作为上下文」等。保留文章真实标题、骨架节点、导读正文和必要的操作/异常/证据状态。骨架默认只呈现主要节点，不附逐项说明小字；不展示推荐首问或固定的下一步追问。输入框只用「输入消息…」。原型场景/说明收进默认折叠的「原型」菜单，正式界面无该菜单。

### 4.2 窄屏

工作区宽 < 960px：同一页面「原文 / 对话」两视图，各保留滚动位置和输入；不是两个业务入口。点击回答证据切到原文，显示固定的「返回回答」；回去恢复该回答位置与焦点。默认打开对话开场，页头清楚显示原文可切换。触控目标至少 40px，编号本体可小但外层命中至少 40px。

### 4.3 颜色与层级

直接引用现有 canvas/surface/ink/accent/mark/anno token，不复制一套硬编码主题。蓝色用于交互位置/选中，琥珀用于原文证据；用户重点保留既有黄色加粗，备注保留既有虚线/灯泡。模型证据不加粗，通过细下划线、编号、浮卡「本轮证据」与用户标注区分。两者重叠时保留用户底色/字重，用证据边线和编号表示附加关系，不混色变脏。

全文不再随阅读镜头把远处文字降色；正文始终稳定可读。浮卡只用既有 popover 阴影，禁止霓虹、渐变聊天背景、呼吸光或大面积蓝色。

### 4.4 笔记/译文/博客

不设常驻第三栏。笔记按需面板在阅读区域覆盖，不改对话归属；关闭回到触发按钮。已有高亮、句子备注、小段笔记、整篇笔记数据完整保留。译文按需展开/切换，点击原文证据必须返回原文层并说明，不能在译文上伪造逐字对应。带读博客入口位于更多，不阻挡主流程。

## 5. 回答证据契约

### 5.1 所有权与身份

新增 AnswerEvidence（拟议术语，正式开发时写入 CONTEXT），属于 FOCUS Discussion 的具体回答修订，不是 Reading Note 或 Reading Highlight。稳定身份至少：`workspace/sourceId/bundleVersion/discussionId/messageId/answerRevision/evidenceId`。可选 Plan/Chunk 用于兼容，不能作为全文唯一锚点。

每条证据包含：

| 字段 | 含义 |
| --- | --- |
| claimId / segmentId | 回答中被支持的论点/稳定文本片段；不能只存会随流式变化的字符位置 |
| kind | source_text / source_object / external |
| source locator | 原文版本、行号闭区间、稳定 blockId；文本另有 exact/prefix/suffix，图表公式另有 objectId |
| resolution | pending / exact / block / unavailable / historical |
| relation | supports / contradicts / context；原文出现不等于支持结论 |
| displayNumber | 回答内稳定序号，按首次出现分配；不是数据库身份 |
| external | 实际来源标题、规范 URL、访问记录；不能投影到左侧 |

一论点可有多个证据；同一原文可支持多个论点/回答。同一回答内相同锚点去重，共用序号；跨回答序号重新开始。当前活动回答唯一，旧回答证据可恢复。

### 5.2 生成与校验

模型先经 search/read_range 获取绑定来源，再提交结构化引用候选（建议扩展 focus 工具 `answer_evidence`，由 Host 绑定消息身份）。Host 校验来源/版本/读取范围/引文/对象；模型不能自选工作区、伪造已校验状态、传 DOM 选择器或 HTML。校验位置存在仅证明可追溯，不证明论点正确，仍须在回答中保留作者条件与推断边界。

回答用稳定片段/引用标记关联证据，而不是对已渲染正文做脆弱的字符串编号替换。中断、重连和重放保持引用身份；未知标记不渲染为可用引用。增量事件建议：answer.started、answer.segment、evidence.validated、evidence.unavailable、answer.completed/failed/stopped，均带 runId/messageId/revision/seq。

正文可先到，校验后的引用再到。候选待定时显示克制的「核对原文」，不高亮、不自动跳。已校验事件与消息片段都到达才允许联动；乱序缓存，按幂等键去重；丢片段时请求快照。重连快照只恢复样式，不重新自动定位。

### 5.3 排版定位

从同版本 Markdown 解析树建立行区间 → 稳定块 → 渲染文本节点映射；保留 Markdown source position，在 sanitize 后以受控属性加入块身份。不得用整页 innerText.find 或任意模糊最近句。

文本：在声明块/范围内验证 exact，再用 prefix/suffix 消歧；统一换行、实体和空白规则，并明确前端 UTF-16 与后端字符串索引转换。显示偏移是派生缓存，原文版本/行范围/引文才是证据依据。强调、链接、脚注、代码、跨行文本都需映射测试。跨块引用拆成子 range，共享同一 evidenceId。

无法逐字映射但原文块已验证：resolution=block，突出段落边界并在卡片写「段落定位」。不存在、多义且无法消歧、版本不一致：不猜测，标「无法定位」/「历史版本」，提供引用文本和可用的历史原文。对象使用 objectId 与解析来源映射，公式/表格支持整体框选；精确单元格必须有验证映射，否则表级定位。

正文采用 CSS Custom Highlight 或等价独立 range 层，编号为可聚焦按钮，避免插入 mark 破坏用户选区/备注。优先级：当前浏览器选区 > 用户永久标注语义 > 活动证据边线/底色。重叠证据在块边缘合并为可操作编号组，不嵌套按钮。

## 6. 联动状态机与滚动裁决

界面状态：activeAnswerId、focusedEvidenceId、previewEvidenceId、popoverOpen、autoLocateConsumed、manualBrowseSinceSend、documentReturnAnchor、chatReturnAnchor、followChat、sourceEpoch。原文高亮持久化的是证据关联，不是每次 hover 状态。

| 事件 | 原文 | 对话/浮卡 | 滚动与焦点 |
| --- | --- | --- | --- |
| 发送问题 | 保留上一回答高亮，直到新回答有有效证据 | 草稿引用冻结 | 不因发送立刻移动原文 |
| 首个有效原文证据 | 激活该回答并标亮 | 显示一个非模态浮卡 | 本轮仅一次自动机会；原文自发送后未被用户滚动/选文/导航、未选历史回答、页可见且宽屏才可自动定位；不抢键盘焦点 |
| 后续证据到达 | 增加当前回答标记 | 同步可点击编号 | 不跳转、不换卡、不覆盖用户查看 |
| 用户主动滚动/触摸/滚动键/选择文本 | 高亮保留 | 浮卡关闭，保留「查看本轮证据」提示 | 立即取消正在运行的程序滚动；本轮自动机会禁用 |
| hover/focus 右侧引用 | 可见目标临时加边线 | 引用处短摘要 tooltip | 不滚动、不切换活动历史回答；focus 可预览，Enter 才定位 |
| 点击/Enter 引用 | 显式选中其回答与证据 | 打开原文附近非模态卡 | 可滚动目标到顶部留白 64px；记录返回位置；键盘操作即时定位并把焦点交给目标编号 |
| 点击原文编号 | 保持证据可见 | 右侧定位关联论点并突出边线 | 仅对话滚动；键盘焦点到回答引用；多个关联可选择 |
| 点击历史回答「查看证据」 | 只显示该回答证据 | 不自动打开卡 | 不移动原文；点击具体编号才定位 |
| 关闭卡 / Escape | 保留高亮与活动回答 | 关闭浮卡 | 用户触发的浮卡将焦点还给触发按钮；自动卡不转移焦点 |
| 返回刚才位置 | 恢复原文书签 | 关闭卡 | 不改变业务进度，不建立递归返回栈 |
| 来源切换/新修订 | 清空旧显示投影 | 取消旧事件、保留旧历史资产 | sourceEpoch 阻止迟到事件写进新文章 |

第一次有效证据已在视口内时不滚动，仅浮卡；自动机会仍消耗。首个有效证据到达时用户已在历史回答，不能抢回最新回答。窄屏绝不自动切换视图：显示「本轮有 N 处原文依据」，用户点击才切换。

对话自动跟随独立于原文：距底部 ≤48px 才跟随增量；上滚立即停止，显示「回到最新」。阅读原文不关闭聊天跟随；阅读历史聊天不影响原文手动位置。流式增量不逐字播放动画。

浮卡宽度 280–340px、距锚点 8px、距容器边缘至少 12px；放置优先在目标下方空白，碰边翻转/夹紧，最大高度 min(220px, 可用高度)，内部滚动。不能越过分栏遮挡输入框。用户滚动关闭卡，显式定位可重新打开。窄屏使用非模态底部证据卡，原文保留可滚动空间。

## 7. 动效设计

沿用现有 quick=140ms、move=240ms、travel=380ms、exit=170ms、fade=120ms；ease-out 为 cubic-bezier(.22,.8,.24,1)，ease-inout 为 cubic-bezier(.45,0,.2,1)。本功能优先 140/240ms，不为已有 380ms 创建新的长入场。

| 动作 | 规则 | 中断/低动态 |
| --- | --- | --- |
| 证据底色出现/消失 | 底色立即更新；可选独立轮廓 opacity 140ms，不逐字扫光 | 高频切换即时；低动态即时 |
| 浮卡入场 | opacity 0→1、translateY(4px)→0，140ms/out，origin 指向锚点 | 用 transition 可逆；低动态仅 120ms opacity |
| 浮卡退出 | opacity→0，120ms，无退出位移 | Escape 立即解除交互，动画不阻塞焦点归还 |
| 引用定位 | rAF scrollTop，240ms/out，距离极大也不延长 | wheel/touch/scroll key 立即取消；键盘触发或 reduced-motion 即时 |
| 右侧关联论点强调 | 细蓝色边线，140ms opacity 后保持选中 | 无闪烁，不改变文字字重和换行 |
| 新回答 | 容器一次 120ms 淡入，历史恢复不播 | 内容增量即时；低动态可直接显示 |
| 目录/笔记面板 | opacity + translateX(12px)，240ms/out；退出170ms/out | 反向从当前帧继续；低动态仅淡入 |
| 分栏调整、场景切换、键盘切换、主题变化 | 即时 | 不动画宽度、全文 reflow 或主题颜色 |

动画仅表达位置、关联与反馈；业务调用不等动画。禁止弹簧回弹、持续呼吸、高亮闪烁、字词依次出现。滚动是定位所需的受控 JS 例外；除此尽量仅 transform/opacity。不用 transition:all。

## 8. 阅读状态与兼容

新增 Reading View Bookmark（拟议显示状态）保存 source/bundle/blockId/offset/lastManualLocation；它不是 Reading Cursor。程序查看证据只写临时位置，退出/刷新优先恢复最近手动位置，不能把每次证据跳转当作阅读推进。

新界面不以滚动或对话修改旧 Chunk 前沿、不生成伪 Reading Progress Entry。显式「标记读完」需 Source/Bundle 级幂等完成操作，旧逐段完成记录保留；旧来源首次进入用旧前沿作为初始书签，不反写旧前沿。新完成状态与旧状态的聚合策略见实施计划，必须带新版本元数据，回滚不能把所有旧 chunks 人工补为已读。

Fresh Reading Session 在新界面只新建/切换 Discussion，左侧全文保持；历史消息仍可找回。Clear/Reset 沿用既有明确确认范围，并将新证据、摘要及关联恢复状态纳入清除事务与写者 fencing。Source Note/Highlight 独立归属不变。旧聊天无结构化引用时可正常显示，不能离线凭文字捏造证据。

## 9. 故障、性能与无障碍

开场失败可重试且原文/对话不受影响。回答失败/停止保留已生成内容和已校验证据，标记不完整；未验证引用不被升级。断网重连以快照恢复，不重复发送、不重复自动滚动。版本变更时旧回答标历史，只有同版本原文可展示精确高亮。书签失效时退回可验证章节并通知一次。

全文逻辑完整，允许按章节虚拟化/图片懒加载；定位不可见块必须先装载并测量，图片预留尺寸，加载后锚点修正。不得为「全文」一次复制所有大图或所有 DOM 节点。开发验收用 100k 字符/1500 块及多图样本：记录首屏、输入延迟、定位耗时，目标现有开发机首屏内容 <1s（不含解析和模型）、点击到高亮 <300ms 已载入/<1s 未载入；未达标记录具体设备和原因，不宣称普适。

编号有「证据 2，实验设置，定位原文」等可访问名称；不用颜色作为唯一区别。浮卡 role=region/非模态，不强制 focus trap；目录模态抽屉才使用适当焦点约束。aria-live 只播报证据数量/完成/失败，不播每个 token。支持 Tab、Enter、Escape、分栏键盘、IME Enter 不误发、200% 缩放、浅/深色、reduced-motion。

## 2026-11-15 逐段精读保留修正

用户明确要求统一阅读入口内保留「逐段精读」和「对话」两个 tab。逐段精读复用原阅读器、Plan、译文、批注及 Cursor 推进流程。对话 tab 使用全文与回答证据联动。切换 tab 不视为读完或推进一段，已有准备好的计划直接恢复。首次尚未准备好的文章会启动原准备流程，完成后再次打开逐段精读。

原文中将逐段精读主流程视为被整体替代的条款由本项修正覆盖。旧逐段精读属于正式支持的阅读方式。

回归验证通过 17 项，包括从精读推进下一段、切到对话、再返回同一段。类型检查通过，构建结果见 tabs-build.log。
