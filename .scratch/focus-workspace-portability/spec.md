# 工作区独立与首次初始化

Status: ready-for-agent

版本：正式规格，2026-10-06。产品决定 Q1–Q11 已确认，Q12 按用户最新要求取消独立 Windows 发行包；用户授权判断并减少票数，本规格由三张纵向实施票交付。

## Problem Statement

用户需要一个可以快速开始阅读、独立保存资料的 FOCUS 工作台。现有启动流程在打开界面前就依赖指定知识库，完整用户资产又分散在知识库与绑定绝对路径的 Host 存储中；更换安装目录或恢复备份，不能保证讨论、阅读进度和后续业务一起恢复。首次配置也缺乏清晰的工作区选择入口，后端固定模型列表与运行依赖增加了理解负担。

本轮按尚无用户的新产品处理。现存阅读记录不构成兼容要求，不实现旧布局转换。需要保护的是本轮新格式首次发布后产生的完整工作区，以及用户明确保存的机器配置。

## Solution

把 FOCUS Workspace 定义为独立于程序安装位置的完整私人阅读数据集合。它包含 Knowledge Base、FOCUS Discussions 和必要的业务恢复信息；凭据、机器配置、原生 Runtime 会话与可重建 Host 状态在外部管理。共享 Application／Core 继续决定全部业务状态转换。

没有保存工作区位置时，先打开与现有主题一致的简洁初始化页。用户原地导入已有新格式工作区，或选择父目录新建工作区；可选择 Codex 或 DeepSeek，连接检查和模型手选均可跳过。成功进入后自动记住位置，正常重启直接打开。

设置提供空闲时更换工作区和“保存并应用”后端设置。新工作区可在退出 FOCUS 后通过完整目录复制备份，恢复后直接导入。沿用现有本地项目启动方式，项目程序与数据目录独立，程序更新或搬动不影响工作区选择；不新增发行包交付。

## User Stories

1. 作为首次使用者，我希望在没有配置时先看到初始化页，以便不用先理解启动命令和磁盘布局。
2. 作为首次使用者，我希望看到“导入工作区”和“新建工作区”，以便根据是否已有资料快速进入。
3. 作为用户，我希望导入直接打开所选目录，以便不会产生不明副本。
4. 作为用户，我希望新建时选择父目录并使用可改名的默认名称，以便容易决定保存位置。
5. 作为用户，我希望已有文件不会被新建操作覆盖，以便可以放心选择位置。
6. 作为用户，我希望系统拒绝无效或不兼容目录并说明原因，以便选对工作区。
7. 作为用户，我希望取消目录选择不会产生新工作区或改动配置，以便可以重新考虑。
8. 作为用户，我希望确认进入成功后才记住工作区，以便失败操作不会成为默认启动目标。
9. 作为用户，我希望正常重启直接回到已选工作区，以便不用反复配置。
10. 作为用户，我希望路径失效时能重新定位原工作区，以便移动目录后继续使用。
11. 作为用户，我希望找不到工作区时不会自动得到一个替代空库，以便知道实际发生了什么。
12. 作为用户，我希望目录选择针对运行 FOCUS 的这台电脑，以便路径与实际存储一致。
13. 作为用户，我希望首次预选 Codex 且可改选 DeepSeek，以便用少量操作确定后端。
14. 作为用户，我希望未联网也能选择“使用默认模型”，以便可以先进入工作台。
15. 作为用户，我希望两个后端分别记住模型选择，以便切换回来不用重新配置。
16. 作为用户，我希望能恢复“使用默认模型”，以便取消之前的手选覆盖。
17. 作为用户，我希望连接检查实际验证一次最小模型调用，以便结果有明确含义。
18. 作为用户，我希望检查成功后看到真实模型清单，以便不会选择前端编造的选项。
19. 作为用户，我希望更换模型不自动发起额外检查，以便保持可控的配置流程。
20. 作为用户，我希望能主动重检当前模型，以便验证新的选择。
21. 作为用户，我希望能区分后端已连接和当前模型已验证，以便不会误读检查结果。
22. 作为用户，我希望清单加载失败时仍能默认进入，以便可选配置不阻止阅读。
23. 作为用户，我希望检查失败后也能稍后配置并进入，以便先浏览已有资料。
24. 作为用户，我希望跳过检查不会暗中安装依赖、登录或调用模型，以便跳过行为符合界面承诺。
25. 作为用户，我希望只在需要时准备所选后端的依赖，以便减少初次等待。
26. 作为用户，我希望复用已有 Runtime 和 Codex 登录，以便避免重复安装或重复账户配置。
27. 作为用户，我希望未登录时有明确的主动登录入口，以便自己完成授权。
28. 作为用户，我希望密钥始终由本机 Host 读取，以便不会出现在浏览器投影或工作区备份中。
29. 作为用户，我希望界面简短说明 `.env` 的实际位置，以便需要时能找到凭据配置。
30. 作为用户，我希望初始化沿用现有主题且不出现大量高级字段，以便快速上手。
31. 作为用户，我希望设置空闲时一次保存并应用，以便不需要另行刷新网页。
32. 作为用户，我希望编辑和连接检查不改变当前后端，以便可以安全尝试选项。
33. 作为用户，我希望应用失败后继续使用原配置，以便失败不会悄悄改变下一次启动。
34. 作为用户，我希望有任务时不能切换后端或工作区，以便执行过程保持一致。
35. 作为用户，我希望设置中可以导入或新建另一个工作区，以便重新选择数据位置。
36. 作为用户，我希望更换失败仍能留在原工作区，以便避免丢失当前入口。
37. 作为用户，我希望其他浏览器页面能识别工作区已更换，以便旧页面操作不会写入新库。
38. 作为用户，我希望来源、专题、博客、计划、译文、笔记、进度与讨论都随工作区保存，以便备份是完整的。
39. 作为用户，我希望重新阅读与清除通过同一业务规则执行，以便界面、重启恢复和后端切换行为一致。
40. 作为用户，我希望停止后能由新的工作台进程接管工作区，以便重启和恢复备份后还能继续写入。
41. 作为用户，我希望已取消或旧进程的结果不会在接管后提交，以便保留有效成果且避免重复写入。
42. 作为用户，我希望同一工作区不能同时被两个写入者使用，以便文件不会相互覆盖。
43. 作为用户，我希望退出后复制整个工作区就能备份，以便无需理解数据库内部结构。
44. 作为用户，我希望备份在新位置导入后保留讨论与阅读位置，并可继续处理，以便恢复具备实际用途。
45. 作为用户，我希望移动或更新程序不会重新创建知识库，以便程序和数据各自管理。
46. 作为用户，我希望项目或工作区路径包含空格或中文时同样可运行，以便自由选择保存位置。
47. 作为用户，我希望缺少可选 AI Runtime 时仍可打开初始化页及已有内容，以便基本使用不被后端环境阻塞。

## Implementation Decisions

### 数据归属与格式

- 一个 FOCUS Workspace 包含一个 Knowledge Base，以及 Source 绑定的完整 FOCUS Discussions、讨论摘要、阅读时间线、持久业务任务与必要的幂等回执、编辑／清除恢复记录。正式来源和阅读资产仍只保存一份；不建立第二套业务权威。
- 机器用户配置记录工作区稳定身份、当前路径、当前 Backend 与各 Backend 的模型偏好。模型偏好区分“使用默认”和“显式模型”，默认值由 Host 的发布配置统一解析；前端不再维护另一份默认模型或伪供应商清单。
- 凭据、Runtime 安装位置、原生会话恢复引用、机器诊断和可重建浏览器投影不作为便携业务资产。原生会话句柄不跨工作区或机器恢复；新执行使用可移植讨论和来源上下文。
- 新格式带稳定工作区身份、格式版本与读写兼容信息。身份与绝对路径分离，来源及内部引用使用稳定身份和工作区相对资源；位置变化不改变 Source、Plan、Discussion 或工作区身份。
- 本轮只创建和导入新格式，不兼容现有或更早布局，不扫描磁盘推断旧用户数据。格式不支持时在任何业务写入和恢复前拒绝打开；不要将业务修订号当成格式版本。
- 复制备份保留逻辑身份，但运行实例和写入资格重新取得。文件锁保障本机同一目录的支持入口；不宣称能够协调不同复制件或跨机器并发，也不引入云同步。
- 允许清理现有 FOCUS 运行数据，但清理只针对实施时枚举、确认归属的目录，不使用宽泛目录名匹配删除；源码、工程文档、凭据和个人 Runtime 状态保留。首次发布后的新用户工作区受本规格的保护和恢复约束。

### 共享业务与写入生命周期

- 重新阅读、清除、Source 管理与其恢复、讨论上下文策略由共享 Application／Core 实现。Host 负责生命周期、网络、浏览器投影和适配，不直接修改 Cursor 或另行实现业务状态转换。
- 单写者获取、释放、崩溃恢复和接管通过同一受控入口完成，覆盖所有受支持写入路径。持久业务归属不能永久绑定某份机器 Host 存储中的写入者 ID。
- 写入资格绑定当前打开实例的代际；业务请求和 attempt 校验来源、版本、幂等身份、取消状态及写入资格。取消先失去提交资格，再尝试中断 Runtime；旧实例迟到事件无法写入接管后的数据。
- 正常退出停止并等待业务写者，持久化可恢复状态，完成数据库落盘并关闭句柄后释放锁。崩溃后只有确认独占权的实例可恢复；恢复不盲目重做已提交成果或结果未知的远端操作。
- 方法、UI、解析脚本等资源按当前项目实际位置加载，不依赖启动终端的工作目录，也不将项目资源路径当作用户数据根。仅整理完成数据独立所需的接口，不为已取消的发行包强制搬迁全部 Core 包或引入打包兼容层，不建立第二份编辑源。

### 未绑定启动与导入／新建

- 常规启动先读取本机配置；没有工作区路径时只提供初始化和后端配置能力。不得提前创建默认知识库、打开业务存储、触发恢复或取得一个虚构工作区的写入身份。
- 初始化提供工作区操作、简短位置显示、Backend 单选、各 Backend 的检查和模型选项，以及进入工作台按钮。高级 Runtime 路径、详细日志、依赖版本和复杂开关不占据首屏。
- 选择本机目录由 Host 提供目录选择能力，并保留手动输入路径。路径来自运行 Host 的机器，普通浏览器目录上传不作为工作区导入；本期不提供远端浏览器的客户端磁盘接入。
- 原地导入先只读识别和校验新格式，再获取独占权和打开。空目录提示新建；其他文件目录、损坏目录、占用目录、不兼容格式均给出可行动错误，保持原数据不变。
- 新建先选择父目录，名称默认 `knowledge-base` 且可以修改。目标已有工作区时提示导入；其他非空目标拒绝覆盖。用户确认之前不落业务目录，取消选择不改变配置。
- 进入操作只有在工作区可用、必要配置保存成功后才报告成功；失败保持初始化页和可重试草稿，不保存不可打开的默认路径，不把半完成目录伪装成正常工作区。
- 有有效配置时直接打开；路径缺失、不可访问或身份不符时展示重新定位入口并保留原配置供辨认。用户可重新定位原库，或明确导入另一库／新建；禁止在原位置静默创建空库。
- 本机用户配置位于工作区及项目程序资源外，正常更新不会清空。`.env` 的定位相对于明确的项目目录，而不是启动终端的当前目录。

### Backend、连接检查与模型发现

- 首次默认 Codex。各 Backend 保存独立模型偏好，切回时恢复；只有一个当前生效配置，跨工作区沿用同一应用用户偏好。
- 未检查时下拉保留“使用默认模型”这一配置方式，可浏览已有已保存选择，但不能提供新的伪造可选清单。没有真实清单不妨碍默认进入；用户回到默认会清除对应手选覆盖。
- 首次检查以发布版本默认模型执行一次没有业务工具或私人来源的最小推理。执行成功后获取该 Backend 的真实模型清单；Codex 使用选定 Runtime 的目录，DeepSeek 使用对应供应商目录和当前调用路径可支持的模型。
- 检查和清单获取不改变生效配置、不创建 FOCUS Discussion、不写来源业务资产。密钥只在服务端使用，日志和错误投影进行脱敏。
- 模型清单成功只表示可选择，不表示清单内所有模型已通过推理或全部 FOCUS 业务。后端、实际 Runtime、认证配置版本和被检模型共同限定检查结果，迟到响应不能覆盖新的选择状态。
- 改选模型保留同一有效环境下的目录，不自动再发推理；当前模型验证标记随之失效，用户可主动重检当前选择。检查失败不清空用户偏好、不静默切换其他 Backend 或模型。
- 检查成功但清单加载失败时，分别显示两个状态，允许重试清单或使用默认进入。手选模型后来不可用时保留选择并给出操作提示，不暗中改成另一个模型。
- 跳过检查或检查失败后进入，不触发新的安装、登录、模型推理或模型发现；允许本地读取状态。需要 AI 的任务按实际准备／认证结果显示错误，已有来源、博客、译文、笔记和进度仍可浏览。

### 依赖与配置应用

- 用户点击检查或首次显式发起 AI 任务时，才按需准备所选 Backend 缺失的依赖。优先复用本机已有 Runtime，显式指定路径失效时报告错误而非偷偷换路径；不准备未选 Backend。
- 依赖准备过程可见，失败后可重试，不把安装成功当成连接成功；首次 AI 任务等待准备结果，失败不能启动另一个供应商的任务。
- Codex 使用已有登录，未登录时提供主动登录入口，用户触发后才开始授权。DeepSeek 等密钥来自明确环境配置；工作区及浏览器不得得到凭据正文。
- 设置使用一个公共“保存并应用”操作，由 Host 原子地约束空闲状态、并发变更和成功结果。编辑与连接检查不会激活配置；运行任务或正在执行的批次不允许变更。
- 跳过连接检查已经被允许，保存应用不重新引入强制远端推理门槛；未就绪的 Backend 可保存为待用户实际使用时配置的选择，界面不得宣称已连接。
- 文件保存或应用失败，旧的已保存及生效配置保持一致，用户草稿可以保留重试。结果未知时重新读取权威配置判定，不由浏览器猜测成功；失败变更不能在重启时被悄悄应用。
- 成功应用更新所有页面的权威状态；已存在 FOCUS 讨论、笔记和阅读位置保持不变。不再保留要求用户另行刷新才能启用的产品流程。

### 空闲切换工作区

- 设置入口复用导入／新建，不提供最近列表、多个工作区并行打开或每个浏览器独立绑定。后端、登录和应用偏好不随工作区文件复制。
- 切换在 Host 侧再次确认没有运行任务，并与新任务启动串行协调。目标打开、配置持久化和生效切换作为一次受控操作；任一步失败，原工作区及原持久选择保持可用，释放新目标已取得的资源。成功后更新本机选择并释放旧写入者，结果未知时读取权威绑定状态，不盲目重做切换。
- 所有业务请求、SSE 投影和异步回调绑定打开实例，不能只比较可能由备份复制保留的工作区身份。旧实例请求被拒绝，避免同 ID 恢复副本绕过检查。
- 发起页进入新工作区；其他页面显示工作区已更换并暂停旧操作，重新加载后接入新库。旧草稿不自动提交，也不静默改绑到新库。

### 备份恢复与项目目录独立

- 本期备份操作是退出 FOCUS 后复制完整工作区目录；说明明确必须停止全部写入并完成落盘。不能把正在运行时单独复制数据库主文件称为完整备份。
- 恢复使用复制后的完整目录和“导入工作区”，不要求原绝对路径，不要求原 Host 私有数据库，不能依赖原机器的原生会话。恢复后保留身份与用户资产，重新建立合法写入实例并继续处理。
- 同版本和声明兼容的新版本可打开新格式。未来不兼容格式必须在写入前拒绝；本轮不实现通用升级引擎或任意旧版本回退。
- 沿用现有本地项目部署与启动方式，基础 Python／Node 等依赖按既有方式准备，不提供独立 Windows 包或捆绑运行环境。可选 AI Runtime 仍仅在所选后端需要时准备。
- 在基础依赖已准备好的前提下，启动工作目录、空格与中文路径不影响项目资源定位。项目搬动或同格式版本更新后仍使用外部保存的工作区选择，不要求重建或重新解析用户资产；不承诺移动虚拟环境目录后仍可直接运行。
- 统一提示“项目目录的 `.env`”，提供不含密钥的配置示例及简短启动、退出、备份和恢复说明。项目配置独立于工作区备份，换项目目录时保留或重新配置 `.env`，不覆盖已有配置。
- 缺少 AI Runtime 或未携带凭据文件时仍可打开初始化界面及已有内容，相关 Backend 如实显示未就绪；不新增凭据迁移系统。

## Testing Decisions

测试以用户可观察的结果为准，不为函数拆分或目录命名编写镜像测试。验收直接纳入三张功能票，移除发行包验收，不再建立独立验收票。

1. **主要自动化边界：浏览器实际使用的 Host 公共操作。** 新增未绑定启动、工作区选择和配置动作，延续 ReaderHost／HTTP 与权威快照模式；使用真实 Application、Core 和持久化文件，只有外部 Parser／Runtime／模型目录服务使用受控替身。复用既有 Host 配置、入库恢复、讨论、清除和阅读旅程测试的结构。
2. **必要的进程边界。** 独占锁、崩溃接管、持久配置失败恢复及旧 attempt 拒绝必须由独立进程或真实关闭／重开验证，不能仅依赖同进程锁和模拟 close。
3. **浏览器交互边界。** 验证首次初始化、目录选择后备、取消、跳过、真实状态投影、设置保存应用、工作区更换、路径失效及两个页面的旧操作隔离；复用现有工作台组件和浏览器旅程测试。检查主题一致性、键盘操作、清晰焦点与加载／错误状态，不增加无关视觉改版。
4. **真实 Backend 边界。** Codex、DeepSeek 分别完成真实依赖解析、最小连接检查、模型清单加载和所选模型的业务调用；未执行的真实登录或安装场景明确标未测。供应商清单、连接通过、业务通过分别报告，不能用替身证明实际服务已支持。
5. **完整数据恢复边界。** 使用合成来源建立同时含 Topic、Bundle、Blog、Plan、译文、Notes、Cursor、讨论／摘要／时间线和恢复回执的工作区；退出后复制到新位置，隐藏原目录及旧机器会话状态，再从公共导入入口打开。比较完整逻辑数据及资源引用，并验证继续阅读、保存笔记、新增材料和生成博客；无需重新解析已经合法发布的原件。另覆盖有已提交中间成果的未完成任务仅继续剩余步骤，以及远端受理结果未知的任务在导入或重启后保持待确认状态、不自动重新提交。
6. **项目与数据独立边界。** 沿用当前项目部署方式并准备基础依赖，验证不同启动工作目录、空格／中文路径和项目位置改变后，资源可正确定位、原工作区可继续打开；缺少可选 AI Runtime 时仍可进入。只验证本期本地运行能力，不要求无开发工具链环境或独立发行产物。

关键反例包括：未绑定时没有默认库；跳过后没有安装或外发；无效导入未写原目录；新建未覆盖；保存失败不改变重启后的配置；切库与启动任务竞态没有双写；清除中断按既定意图恢复；旧模型检查或旧工作区响应不能覆盖新状态；复制来的锁文件不能当作仍有活跃写入者的充分证据。

每张实施票提供本票的确定性、Host 和必要浏览器证据；第一票覆盖真实进程接管，第二票覆盖完整备份恢复，第三票覆盖真实双 Backend 并串联三票的最终用户流程。分别记录通过、失败、未测和阻塞，减少票数不减少这些验收。现有测试基线与本轮新增回归分开记录，历史阶段通过不替代本轮验收。

## Out of Scope

- 完整 DSH 原生工作台、第二套业务实现、完整多宿主交付。
- 当前或更早 FOCUS 数据的自动转换、发现、保全和旧格式兼容。
- 跨机器并发、多写者协作、云同步、共享网络盘协调、运行中热切换。
- 原生 Runtime 会话与内部执行现场无损迁移、个人聊天导入。
- 备份管理 UI、压缩包导入导出、增量备份、自动备份。
- 独立 Windows 发行包、基础运行环境捆绑、安装向导、开始菜单集成、自动更新及跨平台发行验收。
- 初始化高级 Runtime 参数表单、新模型供应商、通用工作流引擎。
- 更改现有解析、博客、阅读和 Notes 的内容质量契约；其既有缺陷不会因本规格标记完成而自动视为解决。
