# 02: 工作区选择、切换与复制恢复

Status: resolved

**What to build:** 没有保存路径时，用户在简洁初始化页新建或原地导入工作区；成功后记住位置并直接进入。设置可以空闲换库，路径失效时可以重新定位；退出后复制完整目录即可备份，并可在新位置导入继续使用。

**Blocked by:** 01 — 完整工作区与安全接管。

## 实施边界

新建、导入、正常打开、空闲换库和路径失效恢复共用一个绑定生命周期。后端配置的完整初始化体验由 03 接入，本票可先使用默认 Backend 验证工作区路径。沿用现有本地项目部署，不交付 Windows 发行包或捆绑运行环境。

## Acceptance criteria

- [x] 未保存工作区路径时 Host 能服务初始化页；不隐式新建默认知识库、不打开业务存储、不取得工作区写者或触发业务恢复。
- [x] 初始化提供“导入工作区”和“新建工作区”，使用运行 Host 的本机目录选择能力并保留路径手动输入；普通浏览器文件夹上传不冒充目录绑定。
- [x] 导入先验证再原地打开新格式工作区，不复制或合并资产。空目录提示新建，非工作区／损坏／不兼容／无权限／占用目录给出具体错误，保留原数据。
- [x] 新建选择父目录并默认创建可改名的 knowledge-base 子目录；目标已有工作区提示导入，其他非空目标禁止覆盖。取消操作不新建目录、不改配置。
- [x] 工作区可用、独占绑定和本机配置保存成功后才报告进入成功；失败留在初始化页并保留可修正草稿，不注册半成品或保存错误路径。正常重启直接打开既有选择。
- [x] 设置显示当前位置并提供“更换工作区”，复用导入／新建；不增加多工作区列表、最近记录或并行打开多个工作区。
- [x] 换库和任务启动由 Host 串行协调；有活动任务或执行中批次时拒绝切换，不能绕过前端限制。目标检查、锁定、激活或配置保存失败时仍保留原已保存和生效工作区，并释放新目标资源。
- [x] 对目标能打开但配置落盘失败，以及响应结果未知给出确定结果：重启不会误用失败目标，未知结果通过权威状态核对，不盲目重新切换。
- [x] 成功换库后发起页进入新库，其他页面停止旧操作并提示重新载入；请求、订阅、草稿和异步结果绑定工作区身份与打开实例代际，旧草稿不自动提交。
- [x] 以相同 Source ID 的不同工作区，以及保留相同工作区 ID 的备份副本验证旧请求隔离；迟到快照不能将新页面切回旧状态。本机 Backend 偏好不因换库重置。
- [x] 保存路径缺失、不可访问或身份不符时展示重新定位／导入其他工作区／新建入口，保留原配置供辨认；不在原路径静默生成替代空库。重新定位原库必须匹配原身份，其他身份按明确导入处理。
- [x] 提供简短说明：退出所有持有该库的 FOCUS 进程并完成落盘，再复制整个工作区；恢复为目录后使用导入。不另找 Host 历史或原生会话，不把运行中单独复制数据库主文件当作备份。
- [x] 以含完整来源、Topic、Blog、Plan、译文、Notes、Cursor、讨论／摘要／时间线和业务断点的合成工作区，停止后复制到不同绝对路径并隐藏原目录；使用全新应用配置从界面导入，核对全部资产和引用，并能继续阅读、提问、保存笔记及新增处理。
- [x] 恢复后的未完成任务只继续剩余步骤，远端受理未知保持待确认状态；已完成成果不因搬迁被重新解析或重做。目录复制成功和页面打开不单独作为恢复验收通过依据。
- [x] 方法、UI、解析资源和项目 .env 按项目实际位置定位，不依赖终端工作目录、不把资源根当数据根；在基础依赖已准备好的前提下，项目位置改变及空格／中文路径不影响原工作区打开。本票不承诺虚拟环境本身直接可搬。
- [x] 初始化和恢复界面沿用当前 Mist 主题，字段和说明精简，键盘及窄屏可用；从浏览器验收取消、导入、新建、失败回退、重启直达、两个页面换库和失效路径恢复。
- [x] 分别记录 Host／进程、浏览器及完整复制恢复证据；本期没有备份管理按钮、压缩包恢复、云同步或独立发行包验收。
