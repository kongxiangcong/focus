# 01: 完整工作区与安全接管

Status: resolved

**What to build:** 用户通过现有工作台完成入库、阅读、讨论和笔记后，全部 FOCUS 用户资产保存在一个新格式工作区内；关闭或崩溃后重新打开，可以恢复并继续处理。另一进程和旧任务不能越过写入资格修改资产。

**Blocked by:** None (can start immediately).

## 实施边界

把必要的清除／重新阅读共享层整理作为票内第一步，再完成完整资产归属与写入者生命周期。使用既有显式工作区入口和现有页面演示，不等待新的初始化页。只整理这条路径所需的存储、业务接口与恢复规则，不扩展成全面 Core／Host 重写。

## Acceptance criteria

- [x] 新格式具有稳定工作区 ID、格式版本及明确兼容检查；独立新建身份不同，根路径改变或复制恢复保留身份，业务修订号不充当格式版本。无效／旧格式在业务恢复和写入前拒绝，不转换现有用户数据。
- [x] Source、原件、Parser Bundle、Topic、Blog、Plan、译文、Cursor、Notes、Reading Progress、完整 FOCUS Discussions、摘要、Reading Timeline 及必要任务／幂等／编辑清除恢复记录全部归属于工作区；不存在必须额外带走的 Host 私有业务历史。
- [x] 资产引用使用稳定身份及可迁移资源关系，不将知识库根绝对路径或机器 Host 存储作为身份；图片、历史原文锚点、讨论和恢复记录随目录保留。
- [x] 工作区路径、Backend／模型偏好、凭据、登录与机器 Runtime 路径在工作区外。Runtime 原生日志和原生会话句柄不成为恢复业务资产的前提，也不被当成 FOCUS Discussion 导入。
- [x] 清除、重新阅读、Source 管理及其恢复、讨论上下文和摘要策略由共享 Application／Core 决定；Host、UI 和 Backend 不再直接改 Cursor 或维护第二份业务规则。
- [x] 清除讨论与笔记只影响目标 Source 的全部讨论、摘要、Notes 及其恢复副本并使原生上下文失效，保留 Plan、Cursor、Blog 和 Reading Progress。重新阅读沿用已接受语义：清除讨论、笔记与阅读记录，所选 Plan 回到第一段但未开始，保留原件、Bundle、Plan、译文、Blog、Topic 和其他 Source。
- [x] 清除或重置遇到活动写者时明确阻止，或先停止并等待实际退出；持久操作记录支持中断后向前恢复，重复请求不会扩大清除范围，旧结果不能恢复已清除内容。
- [x] 所有支持的业务写入口采用一致的独占所有权与打开实例代际检查，覆盖入库、博客、准备、进度、讨论、Notes、管理和重置；第二个进程在业务恢复前被拒绝。
- [x] 正常退出完成业务停止、落盘和句柄关闭后释放所有权；崩溃后新进程可安全接管，不需手工删锁或改 writer 记录。仅有遗留锁文件或复用旧 writer 字符串不决定当前写入资格。
- [x] 取消先禁止 attempt 提交，再中断 Runtime；旧进程／旧打开实例的迟到结果在接管后被拒绝。合法已提交成果保留，幂等请求重放不重复推进或写入。
- [x] 未完成任务在重开后如实显示中断／可重试／结果未知；用户显式继续时只执行未完成步骤，远端受理未知时不在重启或导入过程中自动重新提交，也不自动启动模型。
- [x] 以合成工作区通过现有界面完成入库、阅读提问、保存笔记、清除／重新阅读和重开；校验讨论身份、Source 隔离、阅读前沿、全部持久资产及资源引用。
- [x] 使用真实独立进程验证第二写者拒绝、正常停止／崩溃接管和迟到提交；通过故障注入验证清除中断恢复、候选保留和未完成业务恢复。替身 Parser／Runtime 结果仅作为确定性证据。
- [x] 如需清理已获授权的旧 FOCUS 运行数据，先记录准确路径及归属再清理；源码、工程文档、凭据和个人 Runtime 状态不在清理范围，不以宽泛通配符删除目录。
