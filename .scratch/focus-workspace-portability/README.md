## 合并依据

- 原 01–03 合并为新 01：共享层整理是完整资产与接管的票内前置步骤，通过已有工作台入口验收，不扩展成全面架构重写。
- 原 04、07、08 合并为新 02：新建、打开、换库、路径失效和备份导入属于同一绑定生命周期，统一实施可减少跨票接口反复调整。
- 原 05、06 合并为新 03：偏好、检查、模型发现和应用构成同一配置体验；原 10 的最终串联验收也由本票收口。
- 原 09 删除：不交付独立 Windows 包，不要求捆绑 Python／Node 或无开发工具链启动。项目与数据独立、中文／空格路径、正确资源定位仍由新 02 验证。

## 验收与执行

主要自动化测试从 Host 公共操作连接真实 Application／Core 和持久化存储，外部服务使用受控替身；进程测试验证写者接管，浏览器测试验证实际交互，Codex／DeepSeek 真实连接、模型清单和关键业务结果单独记录。

新 01 承担数据、幂等、共享业务与进程恢复；新 02 承担界面绑定、多页面隔离、完整复制恢复及项目／数据目录独立；新 03 承担真实双 Backend 和三票串联。减少票数不删验收，除已取消发行包外，其余已确认要求均保留。

按 `01 → 02 → 03` 实施，只在当前票必需范围内整理代码，记录本票通过、失败、未测和阻塞。用户授权旧 FOCUS 运行数据可清理，仍需明确实际路径；这不包括源码、工程文档、凭据或个人 Runtime 状态。
