# 01: 依赖、认证与双 Backend 连通检查

Status: ready-for-agent

2026-09-26 用户已确认拆票范围与依赖。本票已发布，尚未实施。

**What to build:** 用户首次准备两套 Backend，能在设置页查看实际 Runtime、完成认证并检查所选 Backend 的真实请求；这条最小闭环同时建立后续业务复用的 Backend 入口。

**Blocked by:** None (can start immediately)。

- [ ] 复用既有 Backend 工厂及事件接口，先完成必要的最小整理，再接入官方 DeepSeek Harness SDK；不另建业务编排器或强制重写 Codex 协议适配器。
- [ ] 首次准备两套依赖：显式 Runtime 优先，其次复用本机安装，缺失才补齐；显示实际路径，分别报告和重试失败；不自动登录或调用模型。
- [ ] 移除 FOCUS 的 Runtime 精确版本和区间门槛；选定 Runtime 实际失败时可见，不偷偷换路径，不提供升级／降级／回退入口。
- [ ] 设置页 Codex 查询并复用个人登录，未登录可发起浏览器授权、等待结果、取消和重试；环境 API Key 不覆盖，所有凭据留在 Host，不读个人聊天或改个人配置。
- [ ] DeepSeek 认证与运行配置由 Host 管理，不隐式借用个人 DSH profile；成功、未配置和失败状态真实可见。
- [ ] 所选 Backend 下方提供连通检查，实际最小模型请求返回成功／脱敏失败；不带私人内容、不开放业务写入、不切换生效配置、不追加讨论。
- [ ] 检查结果绑定配置快照，改配置即失效，迟到结果不覆盖新配置；检查有界结束并释放资源，不把通过解释为完整业务可用。
- [ ] 公开操作测试覆盖路径选择、非历史版本、部分安装失败、认证状态、配置失效和无副作用；分别记录真实 Runtime 最小请求及工具往返／越界拒绝能力探针，尚未覆盖的能力明确列出。
- [ ] 本票的必要设置入口不提前公开运行中切换；应用保存／刷新规则由票 03 完成。SDK 能力不足记录阻塞，不引入普通模型 API 备用路线。

## Evidence

验收遵循父 spec 的最高公共测试边界。记录通过、失败、未测试及阻塞事实；不将替身证据提升为真实 Runtime 或浏览器通过。
