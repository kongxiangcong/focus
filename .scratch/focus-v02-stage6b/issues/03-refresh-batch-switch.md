# 03: 设置刷新生效与跨 Backend 批次恢复

Status: done

2026-09-27 本票实现、公共 Host 契约、双 Runtime 批次恢复、多页面浏览器验收与双轴 review 已完成。

**What to build:** 用户仅在设置页保存配置，刷新时统一应用到全部 AI 路径；批次停止后可改 Backend 并只恢复未完成工作。

**Blocked by:** 02：统一 Backend 的阅读准备、博客与讨论。

- [x] 应用用户级保存配置与 Host 当前生效配置分开；设置按用户跨 Knowledge Base 共用，凭据不进入业务库，不引入第二套业务状态。
- [x] 任一任务或仍在调度的批次运行时，Host 拒绝改 Backend／模型配置；对所有 worker 生效，不能只靠 UI 禁用或只检查聊天。
- [x] 保存未刷新仍可按旧配置启动任务；右下角常驻“配置更改，需要刷新页面”，改回生效配置立即消失。
- [x] 空闲刷新或 Reload 统一应用，手动刷新行为相同；运行中刷新只恢复页面，提示完成后再刷新，既不取消任务也不自动应用。
- [x] 配置保存、应用与任务准入竞争由同一 Host 协调；同一 Host 多页面同步一个生效配置，不允许聊天和后台分别应用。
- [x] 切换不归档或重建 FOCUS Discussion、不改合法资产和 Cursor；隔离原生键与迟到事件，设置页以外无 Backend 快捷切换。
- [x] 批次完成三篇后明确停止、改配置并刷新，再显式恢复／重试：新 attempt 使用新 Backend，已完成步骤复用，前三篇不重做，刷新不自动恢复。
- [x] 连通检查仍只检查设置页选中项，不保存或应用配置；预检查失败不伪装成功或默默恢复其他服务。
- [x] 共同 Host 契约及多页面浏览器覆盖保存后启动、忙时刷新、完成后再刷新、改回值、批次与单项取消；两种真实 Runtime 验证跨 Backend 恢复。
