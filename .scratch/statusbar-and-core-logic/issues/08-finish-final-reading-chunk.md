# 08: 末段触底或行内「读完」提交精读完成

**What to build:** 读者在最后一个精读 Chunk 完成正文时，工作台提交一次完成，并在知识库看到满电和「已读完」。

**Blocked by:** 07 知识库统一按精读进度显示电量和筛选

**Status:** resolved

- [x] 可滚动的末段由读者真实向下浏览触达正文底部后提交。讨论、笔记和留白不改变触发边界。只有当前可见精读的活动阅读前沿可以提交。
- [x] 无需滚动即可完整看到末段时，正文末尾提供鼠标、触屏和键盘可操作的「读完」。底栏保持现状。
- [x] 打开、恢复、自动滚动、证据导航、回看、调整布局、切视图或 Tab、进出全屏、重连和离开都保持原有 Cursor 与进度。对话模式没有完成入口。
- [x] Core 一次性登记末段完成和阅读记录。重复触发、请求重放和过期的来源、计划、轮次或前沿都不能重复写入或改错来源。
- [x] 通过真实工作台验证长末段及短单段，从 `0/1` 或多段前沿完成后能在知识库看到满电和「已读完」，刷新与重开后仍成立。

## Comments

Chromium 验证滚轮、触屏滑动与滚动条拖动均可完成可滚动末段，键盘与触屏可提交短末段的行内动作。Host 回归覆盖重复请求、过期来源与仅写入一次的末段阅读记录。
