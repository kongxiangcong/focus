# 工作台状态、精读完成与重新阅读

Status: ready-for-agent

## Problem Statement

任务成功后，「已完成」和「已就绪」仍占据任务框或页面；断线恢复后，红条有时依然显示。读者还可能在文章 B 看到文章 A 的错误，或在切换到文章 B 后得不到已保存的精读位置。全屏里按 Esc 可能同时关闭浮层和退出全屏，退出还会丢掉证据定位上下文。精读静止时持续采样滚动位置，也消耗本可省下的资源。

知识库目前同时接受精读进度与独立来源完成记录，读者可能看到一个尚未读完的精读计划被算作已读完。最后一段缺少稳定的完成入口。「新会话」「重新规划」「重新阅读」又分别影响会话、计划和资料，读者很难判断从头开始会保留哪些内容。

## Solution

工作台任务框只显示正在进行、等待审批、仍需操作和未清除的失败。成功任务随状态更新退出；「全部清空」一次隐藏已结束的失败提示，保留仍需操作的任务。切篇和切换阅读方式直接更新标题、选中状态与正文。连接、来源和操作错误在各自的作用域内恢复。

知识库以当前精读计划为唯一依据显示电量与阅读状态。读者主动触达末段正文底部即可完成，短末段有一个可访问的行内「读完」。统一的「重新阅读」在确认后清除旧精读内容和局部批注，保留整篇笔记与原始来源，开启空白讨论并立即重新准备精读。

## User Stories

1. 作为读者，我希望在各页面看到同一个任务框，以便随时查看正在处理的工作。
2. 作为读者，我希望任务成功后立即退出任务框，以便专注于仍需要关注的工作。
3. 作为批量上传者，我希望混合批次只留下仍有工作的子项，以便在其他子项成功后继续处理余项。
4. 作为上传者，我希望待确认、可继续或待核对的条目仍可操作，以便完成上传和发现远端结果。
5. 作为读者，我希望当前审批只有一处可操作入口，以便清楚地批准、拒绝或停止相应任务。
6. 作为读者，我希望审批失效后旧操作入口消失，以便不会对已经结束的请求做决定。
7. 作为读者，我希望用「全部清空」一次隐藏已结束的失败提示，以便清洁任务框而无需逐条审核。
8. 作为读者，我希望刷新后已清除的提示仍隐藏，以便无需重复清理。
9. 作为读者，我希望重试再次失败时看到新提示，以便知道最新尝试的结果。
10. 作为上传者，我希望重复添加原件时能找回该原件的未完成任务，以便恢复原有工作。
11. 作为读者，我希望打开、切篇、切换阅读方式或恢复时只通过标题、选中模式和内容确认位置，以便阅读不被重复提示打断。
12. 作为读者，我希望准备中的精读显示真实准备状态，以便知道何时可读或何处重试。
13. 作为读者，我希望连接恢复后断线提示自动退出，以便准确判断当前连接状态。
14. 作为笔记作者，我希望重连后仍看到需要处理的版本冲突，以便保留自己的编辑并解决问题。
15. 作为读者，我希望换篇后只在阅读区看到当前来源的问题，以便不用判断红条属于哪一篇。
16. 作为读者，我希望全局任务框标出其他来源的失败所属文章，以便需要时回去处理。
17. 作为精读读者，我希望切到读过的文章时直接恢复它的精读位置，以便接着阅读。
18. 作为精读读者，我希望切篇时只恢复已选计划，以便候选计划仍由我决定是否启用。
19. 作为读者，我希望精读未就绪时仍可切回对话，以便先阅读原文或提问。
20. 作为读者，我希望慢请求迟到时不会更换我现在看到的文章或提示，以便放心快速切篇。
21. 作为精读读者，我希望静止时滚动控制器停止逐帧工作，以便减少资源消耗。
22. 作为精读读者，我希望流式跟随、手动停留和布局变动后的位置恢复仍然有效，以便阅读位置可控。
23. 作为全屏读者，我希望 Esc 每次只关闭最上层的浮层，以便按自己的节奏返回工作台。
24. 作为全屏读者，我希望退出全屏后仍能看到当前证据并返回原回答，以便继续核对来源。
25. 作为全屏读者，我希望仍能切换阅读方式，并在桌面宽屏使用双栏，以便保留阅读布局。
26. 作为键盘用户，我希望笔记抽屉和确认框打开时获得焦点、关闭后返回触发处，以便连贯操作。
27. 作为键盘用户，我希望导航分支收起时退出焦点顺序，同时保留离场过渡，以便看到清楚的界面变化。
28. 作为知识库读者，我希望各列表和卡片用同一精读进度展示电量及筛选，以便知道文章读到了哪里。
29. 作为刚开始精读的读者，我希望 `0/1` 也能归为「阅读中」，以便区分已开始与未开始。
30. 作为精读读者，我希望主动滚到末段正文底部时直接完成，以便不必另外找底栏按钮。
31. 作为短文读者，我希望在首屏完整可见的末段点击行内「读完」，以便没有滚动距离时也能完成。
32. 作为读者，我希望打开文章、自动滚动、调整布局、切 Tab、重连和离开页面都不会产生完成进度，以便由我的阅读动作决定。
33. 作为读者，我希望查证据、回看前段或切换原文与译文时保持已读进度，以便从原位置继续。
34. 作为读者，我希望对话和历史独立完成记录都不会把精读标成已读完，以便满电只表示当前计划全部读完。
35. 作为读者，我希望完成后的文章重新打开即可查看已读全文，以便复习内容与讨论。
36. 作为读者，我希望通过一个「重新阅读」入口开始全新的精读与讨论，以便不用判断几个重启命令的差异。
37. 作为读者，我希望确认前知道哪些笔记、重点、进度和旧计划会清除，以便决定是否继续。
38. 作为读者，我希望取消重新阅读后位置、笔记和讨论保持原状，以便放心查看确认内容。
39. 作为笔记作者，我希望重读时保留整篇笔记并清除小段笔记、句子备注和重点，以便整篇心得能跨计划复用。
40. 作为读者，我希望开始新讨论后旧聊天仍存档，模型不再沿用旧聊天或其摘要，以便带着全新的问题重读。
41. 作为读者，我希望确认后立即准备新计划，准备就绪后从第一段进入，以便顺利开始新一轮。
42. 作为读者，我希望生成失败时仍能对话并重试精读，以便偶发错误不中断可用的阅读方式。
43. 作为读者，我希望重复提交、刷新或旧任务迟到都不会复活旧笔记或重复重置，以便新一轮保持一致。

## Implementation Decisions

### Batch A · 任务框、连接与阅读交互

- 工作台沿用当前统一阅读入口的快照所有权。每个工作台页面保持一条 SSE 订阅，精读和对话消费同一快照。保留无工作台管理的阅读适配方式。首个反映成功的快照更新状态摘要、任务框和批次子项，即使先前的批次或 Inbox 列表还在缓存。
- Host 的任务投影覆盖问答、审批、阅读准备、开篇导读、博客、入库、批次和阅读记录整理。投影关联业务目标和尝试，来源已知时带来源标识，继续提供已有的阶段、进度和操作。成功、已就绪和删除的项目退出任务投影。保留执行归档与完整业务记录，以及确认、停止、续接、核对、重试和重复上传恢复语义。审批失效时撤下审批控件，保留实际的问答结果。
- 「全部清空」只隐藏当时已结束的失败提示，运行中、待确认、暂停可继续及远端结果待核对的任务仍有入口。清空不改变原任务，也不启动重试。可见性跨刷新及重启保留；同一请求重放和迟到请求只可清除原尝试，新尝试及恢复后的同一原件按当前状态展示。批量清空的去重记录可限制增长，同时保留重放语义。
- 工作台连接错误在 SSE 重连或健康轮询后清除。来源或文档错误随同来源成功重载或切换来源清除。操作错误与尝试绑定，在相应重试成功、主动关闭提示或离开所属来源后退出阅读区。后台业务失败仍可在全局任务框按来源显示。审批只提供一个可操作入口，同时保留可到达的审批和停止路径。
- 移除「正在阅读 xxx」「已打开」「已就绪」类弹框、浮层和横幅，移除「已完成任务」区及刷新后滞留的已保存提示。笔记保存本身和已有的一次性查看反馈继续可用。精读正在准备时使用正常进度提示。定位临时提示三秒消隐，手动滚动立即清除。重新生成成功、来源删除和新尝试分别清理所对应的过期错误。
- 工作台持有当前 Reading Source 和切换代际。跨来源结果在落地前核对两者。精读切篇时恢复已选且就绪的 Reading Plan 及其持久位置，现有候选计划由读者选择启用。来源未准备好时提供准备或重试及切回对话的入口，读取既有计划与切换阅读方式保持 Reading Cursor。
- 以滚动、尺寸、内容变化、有效流式跟随、动画及短暂位置保持作为采样触发条件。无活动时精读滚动控制器零 rAF 唤醒。保留手动滚动优先、锚点恢复、跟随和返回阅读位置功能。
- Esc 由最上层已打开的对话框、抽屉或编辑器先消费，随后一次 Esc 才退出全屏。进出全屏保留当前证据、原跳转位置和返回路径。全屏内保留模式切换和桌面宽屏双栏。折叠导航分支在离场期间保留过渡，同时退出焦点顺序和辅助技术树。
- 笔记抽屉关闭后回焦。精读中的原生阻塞确认改用现有可聚焦模态对话框。工作区选择的自动聚焦限于独立入口页。统一设置页标题文案并清理未接入的外观保存回调。

### Batch C · 精读完成、知识库电量与重新阅读

- Core 以当前 Reading Plan 的精读前沿决定已读段数。正常推进记入刚读完的 Chunk，回看沿用已读高水位。独立来源完成记录留档，同时退出当前状态、电量、筛选和计数。真实的历史精读进度继续可用。已完成来源重新打开时展示已读全文。
- 只有当前可见的精读正文、当前阅读前沿和真实向下浏览才可触发可滚动末段的自动完成。结尾锚点是末段正文底部。讨论、笔记和留白不延长判定区间。正文完整可见且无需滚动时提供可聚焦的行内「读完」，底栏不新增完成控件。打开或恢复页面、重排、程序滚动、对话、证据定位、视图或 Tab 切换、进出全屏、重连及离开页面维持原进度。
- 通过现有受保护的精读提交边界完成最后一个 Chunk。重复触发、响应重放与过期的来源、计划、轮次或前沿均无法产生第二次提交或错误更新。完成与最后一段阅读记录的登记保持一致。
- 列表、卡片和筛选复用同一精读投影。进入正文前归「未开始」，进入后至全部读完前归「阅读中」，全部完成后归「已读完」。已读零段为空框。正进度至 20% 为红色，超过 20% 且低于 60% 为琥珀色，60% 起至完成前为浅绿，全部完成为深绿满电。颜色采用 02 的语义 token。可获得段数时，显示已读段数、总段数和百分比。辅助技术能读取进度名称和值，颜色之外也能区分阅读状态。准备失败和材料异常的处理入口继续可用。
- 统一用户入口为「重新阅读」。同一个确认框列出进度、旧计划、小段笔记、句子备注和重点的清除范围，说明整篇笔记会保留并开启新对话。取消保留原状态。确认后以可恢复、可重试的方式使旧精读计划及其衍生精读内容、进度和局部批注退出，保存整篇笔记、原件、Parser Bundle、旧讨论和不相关的来源资产。旧讨论消息与摘要从新模型上下文排除。
- 确认后立即准备新计划和对应精读内容，就绪后从首段进入。准备失败保留新讨论和未开始的精读状态，当前来源提供重试。重试沿用已经完成的重置动作。隔离正在运行及迟到的旧写入，避免恢复旧计划、进度、已清除的笔记或模型上下文。

## Testing Decisions

以实际工作台加本地 Host 为主要验收入口。通过页面内容、可操作控件、焦点、滚动位置、持久进度和任务结果判断行为。复用现有浏览器状态清除、准备提示、重复入库、流式阅读、全屏及阅读滚动验证；对难以在浏览器稳定制造的过期请求和故障，复用 Host 公开接口与隔离工作区夹具。用浏览器性能观测核对精读控制器在静止期零 rAF，功能回归以阅读体验为准。

| 场景 | 可观察的验收结果 |
|---|---|
| 成功退出与混合批次 | 首条成功快照后成功项退出状态摘要、任务框及批次；刷新后仍隐藏。并行的待确认、暂停、待核对及失败项提供正确动作。成功执行归档仍可读取。 |
| 批量清空与恢复 | 清空后关闭提示跨刷新和 Host 重启保留；运行或必须处理的项目可用。重放同一次清空时新尝试不受影响。重复上传只恢复匹配原件和对应批次，原解析任务不会重跑。 |
| 连接与错误作用域 | 路由、阅读方式和来源切换期间每个工作台保持一条有效 SSE。重连并收到健康快照后断线红条消失，笔记冲突仍可处理。来源 A 的失败仅在 A 的阅读区和标明 A 的全局任务框可见。 |
| 切篇、准备与提示 | 分别延迟来源 A 的成功和失败响应，先切到 B。B 能恢复自己的已选精读位置，A 不覆盖内容或报错。切到未准备来源仍可准备、重试和切回对话。无重复阅读或就绪提示，也无重复审批。 |
| 键盘、全屏与证据 | Esc 先关闭最上层浮层，再退出全屏。焦点返回启动处；关闭的导航分支退出 Tab 顺序。退出全屏后仍能返回刚才的回答，宽屏双栏和模式切换可用；临时定位提示按时或手动滚动后消失。 |
| 滚动性能 | 静止且无实际动画或活动流式跟随后，观测到精读控制器零 rAF。持续覆盖内容增量、尺寸变化、手动暂停跟随、锚点恢复及再次跟随。 |
| 进入、推进和完成 | 初次进入单段实际为 `0/1` 且归「阅读中」。可滚动末段由主动触底提交一次，完整可见的短末段用行内动作提交。多段逐步推进到满电，完成后重开阅读全文。覆盖重复触发、重放和过期前沿。 |
| 非阅读动作与历史记录 | 单独测试打开、自动滚动、证据定位、回看、切视图或 Tab、全屏、布局调整、重连及离开。Cursor 和已读段数保持原值。覆盖有无当前 Plan 的历史独立完成记录，均不凭独立记录产生满电。列表、卡片、筛选和计数一致。 |
| 重读确认、数据与上下文 | 取消后所有状态保持。确认后旧计划、进度和局部笔记清除，整篇笔记及原始来源可用。旧讨论仍存档，捕获新讨论的首个模型请求以验证旧消息和摘要未被沿用。 |
| 重读失败与并发 | 模拟生成失败、确认响应丢失、Host 重启和旧写入迟到。重置继续到一致状态，期间对话可用；重试从新一轮准备继续，成功后从首段进入，旧资料不复活。 |

## Out of Scope

- 01 的证据签发、版面坐标、统一 IR 和旧 Bundle 重解析。
- 03 的主题选择、全量配色和布局重设计。02 包含已确认的滚动、全屏、导航离场、键盘和电量显示交互。
- 修改入库授权、解析后端、问答审批结果或批次业务状态机。
- 为历史独立完成记录补造精读计划、已读段数或阅读记录，以及批量改写这类历史归档。

## Further Notes

Batch A 可独立实施，保持现有持久化阅读契约。Batch C 依据 ADR 0035 变更完成和重读语义。回归验收保留 01 的来源代际、一次性证据导航和 Reading Cursor 边界。
