# Implementation brief schema

Use this single schema for Tiny, Small and Substantial implementation tasks; the main workflow defines storage and effort. Compress fields into prose for Tiny work. Delivery and redesign documents refer back to this brief rather than copying its fields.

| Field | Required content |
|---|---|
| Goal | Primary content/task, main action and observable result |
| Route and scope | Mode, preserve/redesign policy, size; required-now, required-final, optional, out-of-scope |
| Authority | Selected design file/section/revision, task overrides and superseded visual decisions |
| Surfaces | Product root/output, routes/entry points, target viewports and affected states |
| Contracts | IDs, persistence, requests, drafts, navigation, cancellation/recovery to preserve or explicitly change |
| Ownership | Existing visual/motion source and implementation owners; for Standalone, selected starter |
| Reference | Relevant local snapshot/commit/files or none; link adoption ledger if needed |
| Acceptance | Named action → state/result scenarios; commands, browser checks, realistic data and limits |
| Open items | Remaining decision/blocker and next action, or none |

A blank field is unfinished. “None” needs context when the field could apply. Approval already present in the current task is sufficient; routine implementation choices belong in the brief rather than a new approval loop.
