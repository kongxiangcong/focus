01 — 信息层级

先确定用户正在做什么

当一页内容同时出现正文、工具栏、状态卡片和对话框时，界面首先要回答的不是“使用什么颜色”，而是“这一刻，哪个对象最重要”。

以阅读为例，正文应该保持稳定的宽度和连续的位置。解释、笔记与设置是围绕正文展开的辅助能力，不必永久占据屏幕两侧，也不应该在打开时清空正在阅读的内容。

一个判断标准：用户关闭辅助层后，能否自然回到刚才那句话，而不用重新寻找阅读位置？

查看这一页的交互约定

“继续阅读”只追加下一段，不替换前文；“解释当前概念”打开辅助弹窗，不改变阅读进度。输入中的 Enter 与中文候选确认分别处理。

02 — 用户控制

新内容到来，不等于必须打断阅读

流式回答带来持续变化，但变化不应该抢夺视口。用户向上翻阅时，系统应保留当前位置；只有主动返回最新内容后，才恢复自动跟随。

这需要一个明确的行为状态，而不只是某个滚动动画。下面的状态关系是一种设计示意，并非后台服务的实现承诺。

FOLLOWING → 用户向上阅读 → READING_HISTORY
READING_HISTORY → 点击“回到最新” → FOLLOWING
03 — 有目的的动效

动效解释变化，不替代变化

展开时的一次轻微位移能够维持位置关系，按钮的短暂反馈能够确认操作。但如果减少动效后，用户就不知道任务是否完成，那么缺失的是状态表达，不是更多动画。

这一页保留可见的状态文字，并在系统启用“减少动态效果”时取消非必要位移。模板的回答是本地演示，页面不会发出网络请求。

正文与解释互相独立，阅读进度只由“继续阅读”推进。
