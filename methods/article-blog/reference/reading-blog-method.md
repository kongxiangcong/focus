# 技术细读型博客：article-blog 带读博客方法

本手册指导 article-blog 的 Reading Blog（带读博客）将论文转为技术讲解型博客。沿用 Lilian Weng 风格的研究长文取向：围绕问题组织材料，解释方法成立的原因，以技术证据支撑结论。不做逐段翻译、摘要拼接或按论文章节复述。

## 1. 目标与交付

输出 Markdown（`.md`）。标题点明研究对象与问题；导语说明问题、重要性、本文范围及必要背景。正文应让读者能够复述主要模块如何工作、关键技术对象有什么作用、实验支持什么结论。

以提供的论文正文和配图为依据，不固定解析产物的文件名或目录。先整理细读证据，再写正文；证据清单作为写作准备，不强制成为正文一节。

按解释所需决定篇幅与结构，不规定贡献、模块、公式、图表或限制的数量，不为满足栏目而补造内容。

## 2. 写作前：围绕五个问题细读

### 2.1 论文解决了什么问题？

明确任务、现有方法的不足和成立条件。将核心贡献对应到具体机制与证据，避免只写“提出新方法”“效果更好”。

### 2.2 方法为什么成立？

沿“问题 → 约束 → 设计选择 → 结果 → 代价”拆解方法。每个关键模块说明解决什么子问题、输入输出、工作过程、设计动机、自然替代方案与代价。

选择理解核心机制所必需的技术对象深入解释。公式应说明变量、直觉、流程位置及其约束或优化的对象；没有核心公式时，使用论文实际提供的算法步骤、伪代码、接口或复杂度分析，不制造形式化内容。

### 2.3 图表与实验说明了什么？

优先深读支撑核心机制或结论的论文原图与关键实验。流程图解释对象、箭头和数据／控制流；曲线解释坐标、趋势与异常；表格解释指标、基线、主要差异及实验条件。只展开与结论有关的子图和列，不逐项抄录。

说明实验验证什么假设，消融或敏感性结果支持哪个设计选择。结果解释必须受证据约束：区分作者解释、实验支持的判断与本文推测；没有对照证据时，不把相关性写成因果。

### 2.4 实现需要哪些条件？

抽取与论文类型相关的实现、复现设置，例如数据处理、训练或推理配置、硬件、成本和依赖。缺失信息明确列为未交代项；建议采用的假设不能写成作者实际设置。

### 2.5 结论的边界在哪里？

识别限制、失败设定与适用条件，并对应到论文证据或现实约束。开放问题只从实际缺口推出，不为凑数泛泛展望。

## 3. 正文骨架

按以下主线组织，可根据论文类型调整小节名称与展开方式：

**标题与导语 → 必要背景 → 方法与核心机制 → 实验与证据 → 讨论及实现要点 → 参考文献。**

背景只补齐理解本文所需的知识。方法按“直觉 → 形式化 → 实现要点”展开，核心模块分别讲清；公式与图表放在对应的解释位置，不集中堆放。实验围绕假设和证据组织，不只罗列数字。

长文按需提供目录。完整证据地图、开放问题、“如何引用本文”及博客 BibTeX 不作为必设栏目；原论文及实际使用的参考资料仍须完整列出。

## 4. 讲解与引用

首次出现的必要术语、缩写与符号应解释，之后保持一致。叙述为主，模块、流程和比较适合时再用标题、列表或表格。不重复预告每节内容，不堆叠空洞形容词，不大段复制原文。

关键结论、数字、图表和方法来源必须有可点击引用，并尽量定位到章节、公式或图表。文内以作者／团队与年份标识来源；文末编号列出对应资料的标题、作者／团队、年份与发表或资源类型。不要编造作者、发表信息或发布地址。

图片有图注与来源；重画图注明改绘关系。重构表格时区分论文数据与本文归纳，保留支撑结论的条件和数值。无相关原图或实验表时，用已有技术证据讲清机制，不虚构替代结果。

核心公式使用 LaTeX，先说明问题与变量，再给公式并解释其作用。代码只保留有助于理解设计的片段，并标注语言。确保标题层级、链接、图片路径及公式在目标渲染环境下可读。

## 5. 交付前检查

- 核心问题、机制、证据与边界是否形成完整解释，而非摘要拼接？
- 关键公式、图表或算法是否讲清其作用，没有以“概述”代替技术解释？
- 实验结论是否保留比较条件，推测与缺失信息是否明确？
- 引用是否可追溯，术语与 Markdown 是否一致、可读？
- 是否删去重复叙述、配额式填充和无实际内容的栏目？

## HTML Article Source 的证据边界

网页文章沿用同一带读方法。将文章作者的转述、引用的研究结论与解释性推论分开；没有实验、公式或研究贡献时按实际工程内容展开，不为论文栏目补造内容。无编号的章节与图表使用原题或图注，不编造节号或 Figure/Table 编号。
