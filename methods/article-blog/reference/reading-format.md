# Reading Blog 与 Value Analysis 的阅读排版

生成两篇正文时，先理解全文的问题、机制、证据及边界，再直接在 Markdown 中标注重点。不要依赖固定关键词表或把所有英文缩写标粗。

- 每篇只有一个 `#` 主标题；主线章节用 `##`，模块或子问题用 `###`，必要时用 `####`。标题必须独占一行、前后留空行，不用加粗整段冒充标题，不跳级。
- 用 `**专业术语**` 标出理解机制必需的概念、模块、算法或输入输出对象。优先标注术语首次定义或本节首次解释的位置，同段重复出现不再标粗；需要时保留英文原名并用正文解释。
- 用 `==关键结论或因果关系==` 高亮最值得记住的短句，包括核心瓶颈、设计为何有效、关键取舍和适用边界。高亮以原文证据为依据，保留条件、否定和不确定性，不把推论写成事实。不要只高亮孤立的性能数字。
- 每个自然段通常最多 1–2 处加粗，每个主要章节通常 1 处高亮，必要时最多 2 处。普通过渡段允许完全不标注；不为了凑数添加标记。高亮尽量不超过一句话，不把整个段落或所有列表项标亮，不叠加加粗与高亮。
- 每段围绕一个意思，通常 2–4 句；并列要点用列表，对照信息用表格。保留解释链，不因排版缩减关键机制、证据或边界。
- 不在标题、代码、公式、链接地址、图片路径、文献条目中添加重点标记。不要输出 HTML 样式标签或内联 CSS；强调统一使用 `**…**` 和 `==…==`。
- 最后检查：只扫标题、粗体术语和高亮短句，能否看出问题、机制、结论和边界？若标注太密则删减。证据笔记不适用本排版要求。
