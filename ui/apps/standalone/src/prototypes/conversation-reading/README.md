# FOCUS 原文与对话阅读原型

本原型回答：完整原文与持续对话并排时，证据自动出现、用户手动阅读和历史引用如何共存？采用用户已确认的单一方向，场景选择器用于检查状态，不引入多套阅读入口或视觉方向。

## 打开

在仓库根运行：

```powershell
pnpm reader:dev --host 127.0.0.1 --port 5191 --strictPort
```

打开 http://127.0.0.1:5191/prototypes/conversation-reading/ 。若已有该端口的预览服务，直接打开即可。

## 体验路径

1. 首次打开：左边读原文，右边自动呈现中文骨架与一段导读，点击骨架可导航。
2. 在输入框发送「为什么重新分配 SRAM 就可能变快？」：分段模拟回答；三处证据逐步出现，只有第一处自动定位。
3. 点击回答的 [2]/[3]：左侧定位并展开证据卡；点击左侧编号或卡内「查看关联回答」回到对应论点。
4. 发送问题后立即滚动左边：本轮自动跟随暂停，证据仍能点击查看。点击「返回刚才位置」返回。
5. 输入「继续解释阶段切换的代价」新增一轮，再点击旧回答「查看证据」恢复旧高亮。
6. 鼠标选中左侧文字，点击「问这段」；引用条可移除。普通输入按内容关键词选择预设回答，不是真实模型。
7. 右下角展开「原型」后，场景选择可看图表、段落定位、外部补充、定位失败与历史版本；顶部切换浅深色，原型菜单可减少动效。
8. 窄屏在原文/对话间切换；点击证据进入原文，底部「返回回答」恢复讨论。

原型状态仅在内存。笔记、读完标记和草稿刷新即清空。合成英文文章、表格数字、分区示意图均为交互素材，非已发表研究或实验结果。外部链接只是显示示例，点击才访问，未执行联网搜索。

## 本轮产物

- `.scratch/conversation-reading/spec.md`：完整需求与证据状态机、动效和验收矩阵。
- `.scratch/conversation-reading/implementation.md`：模块、数据契约、兼容与实施顺序。
- `.scratch/conversation-reading/issues/01-*.md` 至 `09-*.md`：独立工单。
- `.scratch/conversation-reading/acceptance.md`：本次原型验证及未覆盖项。

原型直接读取现有 focus-tokens.css 和阅读字体。没有改正式阅读入口、后端、模型配置、业务数据或 accepted ADR。正式开发需获用户后续确认，生产必须实现真正的来源映射/引用校验，不能把固定 DOM ID 的演示映射复制过去冒充实现。

## 2026-11-15 界面精简

按用户评审移除额外标题、引导口号、说明小字、推荐首问和固定追问；骨架仅展示节点。输入框简化为「输入消息…」，调试控件收进默认折叠的「原型」菜单。原文正文、导读和证据功能保留。
