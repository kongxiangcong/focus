# FOCUS 用户操作逻辑审查与优化方案 已确认版

本文件是 FOCUS 网页端下一轮修复的已确认需求与验收依据。用户于 2026 年 9 月 30 日确认全部方案，包括 U1–U7、A1–A14、三条核心规则及实施顺序；原可选项 A14 已纳入第四阶段。后续新会话可直接实施，无需再次确认这些需求。

目标是让阅读与提问按发生顺序向下展开，操作名称与实际结果一致，用户随时知道当前在做什么，同时让正文获得更大的可视面积。

审查基线为 main 的提交 [309d6171](https://github.com/kongxiangcong/focus/commit/309d61711db739d59576d7c29201483dee13273f)。实现前应检查最新代码，已修复项验证后跳过。“确定”表示基线代码可以证明；“风险”仍须复现，用户确认修复范围不等于已证实缺陷。

本次只更新需求文档和生成修复提示词，未修改项目代码、未提交或推送。本已确认版基于上一轮完整审查稿更新；原 Pages 页面当前读取失败，尚未原位覆盖。本文件作为后续执行依据。

## 优先结论

先修正操作语义和数据关系，再处理布局与动效。阅读卡片排序、新会话清屏、历史段落继续和重新阅读，都涉及前后端约定，单改样式或按钮文字不能完成。

1. 设置应有明确的“保存设置”，连接检查只返回检查结果。
2. 中间区域应是一条完整时间流：段落 → 提问 → 回复 → 下一段。
3. 区分正在看的段落、已经读到的位置、当前会话显示的内容。回看和清屏不能意外改写阅读进展。
4. 顶部状态条与知识库任务框共用状态来源，任务完成后退出“当前工作”。
5. 重新阅读应是明确的重置操作，保留原件、解析内容、分段、译文与博客。

P0 表示动手前必须统一的行为与数据规则；P1 表示本轮应修正的操作问题；P2 表示后续体验增强。这是实施顺序，不代表安全漏洞等级。

## 阅读流和继续按钮的规则

### 时间顺序与提问归属

普通阅读按以下顺序展示：

1. 第 3 段译文成为当前焦点。
2. 用户提问追加在该段后。
3. 回复在同一张回答卡片内逐步生成，成为当前焦点。
4. 点击继续，第 4 段追加在回答后；第 3 段与其问答留在上方。
5. 新问题默认关联第 4 段；引用历史卡片则关联被引用的段落。

回复必要时显示“关于第 3 段”，不显示内部标识。已有译文直接呈现，无需模拟打字；模型回复使用真实增量。代码已有 SSE 和 message/delta，本次主要修正显示顺序与归属，并非从零建立流式协议。E16、E17、E19。

短卡片可居中；长段落顶部对齐可读区域。长回复开始时定位一次，后续只在跟随最新内容时滚动。用户向上回看后停止自动跟随，提供回到最新。旧内容可弱化，但悬停、键盘聚焦和主动回看时恢复清晰，不能长期难以辨认。

### 回看后的继续

已确认采用“打开眼前段落的下一段”，同时保留已读进度。

| 场景 | 点击继续的结果 | 持久化进度 |
| --- | --- | --- |
| 已读到第 8 段，正在看第 8 段 | 打开第 9 段 | 正常推进一次 |
| 已读到第 8 段，回看第 3 段 | 打开第 4 段，沿历史顺序浏览 | 不倒退，不重复创建已读记录 |
| 回看走到第 8 段后再继续 | 打开第 9 段 | 衔接原进度，推进一次 |
| 全篇已完成，回看第 3 段 | 打开第 4 段 | 保持已完成 |
| 最后一段尚未完成 | 同一位置显示完成本篇 | 明确提交完成 |
| 全篇完成且已到末尾 | 保留结束提示；继续可为禁用态并说明本篇已读完 | 不循环，不自动跨材料 |

Core 仍保存唯一权威阅读进度，界面保存回看位置。不能把历史段落伪装成最新 cursor receipt 传给现有 continue 接口；需要明确区分“浏览已读下一段”与“推进到新段落”。

### 新会话和重新阅读

| 操作 | 阅读空间 | 讨论与笔记 | 位置与内容 |
| --- | --- | --- | --- |
| 新会话 | 清空当前显示 | 旧讨论可从历史打开；笔记和记录保留，新讨论不自动继承旧上下文 | 不重置进度；已展示第 k 段，下次继续开第 k+1 段 |
| 尚未展示过任何段落时新会话 | 空白 | 保留资产 | 继续打开第一段 |
| 重新阅读 | 清空当前显示 | 清除本篇讨论、摘要、笔记及恢复副本、阅读记录 | 重置到第一段待开始；保留原件、解析内容、分段、译文、博客和专题 |
| 重新规划 | 新计划就绪前旧阅读仍可用 | 保留笔记，旧计划记录可回看 | 候选计划就绪后手动打开；失败不破坏旧计划 |

“第一段待开始”必须与“第一段已展示”区分。重新阅读后首次打开或继续显示第一段，不能因游标已是 chunk-001 就跳到第二段。

重新阅读确认文案：“将清除本篇讨论、笔记和阅读记录，并从第一段重新开始。原文、译文和博客保留。”清理与重置必须作为可恢复的完整操作；失败不能留下笔记已清空、位置未重置的半完成状态。旧请求和后台补记迟到结果不得重新写回。

已经完成全文时，新会话也应允许针对材料提问；继续区显示已读完，而不是无响应或隐式重置。

### 已确认的边界处理

新会话继续以本篇最新已展示的阅读进度为准。例如已读到第 8 段、临时回看第 3 段时新建会话，随后继续打开第 9 段；只有保持在回看状态下点击继续，才打开第 4 段。完成状态不因新会话改变。

新会话的清屏边界应在刷新后保留，旧阅读卡片不能因刷新自动回到新会话。重新阅读可直接作用于知识库中的非当前材料，无需先打开它。执行重置时如有相关后台写入，明确阻止或停止并等待其退出，不能与清理并发提交。

笔记与进度清理属于用户在产品内明确确认的重置操作；开发和测试只能在隔离数据中验证，不能据本修复授权清空真实知识库。

## 页面布局和入口

### 阅读页

顶部固定全局状态。右上方专题在上、材料在下，固定等宽；初始宽度可取约 240px，小屏按可用宽度收缩。长标题在固定宽度区域支持横向查看，并提供完整标题显示。不能只给原生 select 加省略号便认定满足要求，应验证键盘、触屏和滚动。

中间只放阅读与问答时间流；底部保留输入框、继续和新会话。右侧以笔记、阅读记录按钮打开资料栏，内部限高滚动，关闭释放正文宽度。历史讨论入口也可放入这里，避免顶部堆叠“讨论 1、讨论 2”。

左侧段落导航继续保留，清楚标出正在查看的段落，必要时区分已读位置。未读段落直接跳转本轮不扩展。小屏资料栏改为抽屉；切换资料栏不能丢输入、笔记编辑或中央滚动位置。

### 知识库

卡片默认只展示一个标题、一行类型或出版信息、一处阅读进度、主操作和更多。标题不再同时出现简称、全名、详情全名三份。

主操作按状态显示：未准备 → 准备阅读；准备中 → 阅读准备中；就绪未读 → 开始阅读；已开始 → 继续阅读；已完成 → 查看已读内容；失败或中断 → 重试准备。博客就绪时提供打开博客。

展开内容不重复标题和进度。重新规划、重新阅读、管理材料、删除材料归入次要操作。原件和正文链接保留，技术诊断折叠。重新阅读与删除材料必须明确区分。

删除独立恢复准备按钮，不等于删除恢复能力。失败恢复由主按钮或任务框接管；任务框仍保留停止入口。准备完成仅通知，用户手动进入，避免阅读其他材料时被强制切换。

### 设置页

统一保存设置和取消修改。连接检查只验证，登录 Codex 只处理登录。反馈使用“有未保存修改”“检查成功，尚未保存”“已保存并生效”“保存失败，修改已保留”。

运行任务时仍可编辑草稿和预览外观。后端配置不能保存时明确等待哪个任务，本次不扩展自动排队切模型。外观与后端分别保存于浏览器与服务器，应如实反馈部分失败，不能一部分失败却显示全部成功。内部路径、凭据位置和版本等继续隐藏。

## 统一任务状态

顶部回答现在在做什么；知识库任务框展示工作清单和恢复入口；折叠详情提供诊断信息。三处共用任务状态，不能各自猜测。

| 状态 | 顶部示例 | 任务框行为 |
| --- | --- | --- |
| 空闲 | 当前无工作 | 完成历史默认折叠 |
| 解析 | 正在解析《材料名》 | 真实阶段和进度；没有百分比不编造 |
| 准备阅读 | 正在准备《材料名》的译文 3/12 | 可停止，失败可恢复 |
| 生成博客 | 正在生成《材料名》的博客 | 保留成功部分，只重试失败步骤 |
| 问答 | 正在回答《材料名》第 3 段的问题 | 可停止；回答仍在阅读流 |
| 补记 | 正在整理阅读记录 | 不阻塞继续阅读 |
| 等待操作 | 有 1 项工作需要你的确认 | 明确入口，不把用户必须响应的事项藏进日志 |
| 多任务 | 正在解析《A》· 另有 2 项工作 | 展开查看各项，不只展示最近创建的任务 |
| 失败或停止 | 当前无工作 · 1 项待处理 | 失败保留到处理或忽略，不假装仍在运行 |
| 断连 | 连接中断，正在恢复 | 保留最后已知状态并标记过时，不能断言空闲 |

“最新”指活动任务最近的有效进展，而不是最后一条历史记录。需要用户处理的事项优先突出；否则可优先显示正在解析的材料，再显示其余数量。

切换页面、刷新和重连从后端恢复活动任务。终态移入历史，顶部显示其他活动任务或空闲。“停止本篇解析”“停止当前回复”分别绑定具体任务，不能全部调用 agent.stop。

正常页面隐藏 Source、Plan、Cursor、Runtime、工具调用和内部状态码。用户看到“材料已入库，专题关联失败，可重试关联”即可；原始错误放查看详情。简化不能隐藏数据风险或必要的失败恢复入口。

## 与既有约定的差异

| 既有约定 | 本次变化 |
| --- | --- |
| CONTEXT 和 ADR 0010 规定回看不授权从历史位置继续 | 增加回看继续；已读范围按浏览处理，不改写进度 |

## 已确认的核心规则

用户已全部确认，后续实现不再重复询问：

1. **回看继续**：从眼前段落打开下一段；已读范围只浏览，不回退持久化进度，不重复记账。
2. **重新阅读**：清除本篇讨论、派生摘要、笔记及恢复副本和阅读记录，重置到第一段待开始。原件、解析内容、分段、译文、博客和专题保留。
3. **新会话**：清空显示并创建独立讨论，保留已有资料和进度；从最新已展示的进度继续到下一段，不受临时回看位置影响。未开始或重置后从第一段开始，全篇完成后保持完成。
4. **完整范围**：U1–U7、A1–A14 全部纳入，按四阶段实施。风险项先复现；已被最新代码修复的项目验证后记录为无需重复修改。

确认方案不代表修复已经完成；原审查证据和测试限制仍然成立。
