# 阶段 5A：另一输入格式与解析能力收口

状态：待 grill。依据：总计划 P3、§7。依赖：阶段 1–4 的单篇流程；默认补 HTML，若首阶段实际选 HTML 则对调。

## 本阶段交付

在同一 Inbox／Application 路径补齐 PDF 和用户选择的单文件 HTML，均发布同一契约 Bundle，并走通博客、整篇问答、独立备注和可选精读。格式差异留在解析适配和证据规则，不复制业务状态机。

现有 HTML Parser 可复用，但方法原先的 PDF-only 前置条件必须在共用 article-blog 方法中消解。非论文文章没有公式、实验或表格时依据真实内容解释，不强塞论文模板。

## 验收出口

- 两种格式各有真实 Parser＋Runtime 的完整场景，覆盖图片、引用和实际内容质量；本地 Markdown 或 fixture 不能替代。
- HTML 缺图、无效文档、访问失败／解析失败给出明确结果；不绕过访问控制或增加发布平台专用采集器。
- 已发布 Bundle 在各下游步骤均可核查来源；错误只重试对应阶段，不重新规划或重新解析整个流程。
- 记录所用云／本地解析器的准确版本和已验证能力；本地 MinerU 若未接通则明确不支持，不作为可静默替换的 fallback。
- 保留现有 Markdown 导入的回归边界；其是否作为新 UI 的正式入口单独明确，不扩大为新的必需解析格式。
