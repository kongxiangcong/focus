# 阶段 5D：旧数据迁移与独立版发布收口

状态：待 grill。依据：总计划 P3、§7–8。依赖：2D、4、5A、5B、5C 的出口证据。

## 本阶段交付

基于阶段 0 的真实旧 schema 盘点，在副本上实现显式迁移、dry-run 和完整性比对；验证正式独立网页版的新流程及旧版本回退。现有 Chunk Notes 迁到 Source 级时保留锚点与历史归属，不凭内容相似擅自合并或补写用户确认。

迁移与同 schema 停机切换宿主是两件事。本阶段完成旧→新数据转换；阶段 6 验证兼容新版本间接管，不要求重新解析已有资料。

## 验收出口

- dry-run 不改原件和旧 workspace，明确转换对象、冲突、未支持 schema 及不可无损映射项；备份可恢复。
- 比对原件字节、Source 身份／Topic 关系、Bundle 与博客引用、备注内容／锚点、Plan／Chunk 与游标语义；保留旧合法译文的映射依据。
- 已有全文译文只作可复用缓存，不能恢复“全文准备才成功”的执行门槛。无法可靠映射时阻止或显式报告，不猜测。
- 部分失败可恢复／重跑，不产生双份权威状态；正式切换有清楚的停止旧写入者、验证新数据及回退步骤。
- 独立网页完成 PDF／HTML、批量、博客、问答／备注、按需精读、管理及失败恢复的真实验收；无需安装 DSH。
- 发布说明记录版本、已验证能力和未通过项；开发辅助 Skills 与产品 Methods 的边界清楚。DSH 探针持续回归，防止公共接口退化为独立 Host 专用。
