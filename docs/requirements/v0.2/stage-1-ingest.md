# 阶段 1：单篇统一入库

状态：已有四票实现及 [2026-09-21 验收记录](stage-1-acceptance.md)；2026-09-22 本轮 grill Q1–Q4 已全部确认并同步至 [本地实施 spec](../../../.scratch/focus-v02-stage1/spec.md)，补充要求尚待实现与验收。本轮未复跑既有验收，不将历史结果视为补充要求已通过。依据：总计划 §1、§3–5、P1／P2。

## 用户结果与范围

用户创建或选择最小 Topic，将一份 PDF 放入 Inbox，检查目标和处理说明，明确确认后得到可查看来源的 Parser Bundle。新版入库到此成功，不创建 Reading Plan，不等待全文译文或博客。

统一使用 article-parser，迁入可复用 PDF 解析、规范化、元数据、组装和导出能力，保留已有 HTML 能力；删除旧 paper-parser Skill 和废弃调用入口，不保留旧名称兼容壳。通过共享 Application 编排并由 Core 校验发布。将必要 Core 能力抽入正常 Python 包、建立最小 Parser／Runtime 接口和统一方法来源；其余必要包装只能单向调用同一实现。只迁本切面需要的能力。

Core 管稳定 Source 身份、解析 ID、Bundle 版本及 Topic 关系；标题路径不是身份。Inbox 项、确认和失败状态要能恢复；失败或远端仍运行时不能伪造正式 Source。原件及证据按 Bundle 契约保留。

## 验收出口

- 刷新后未确认项目仍待确认，无远端解析或模型外发；确认绑定所选文件及目标，修改输入不会沿用失效授权。
- 一份授权 PDF 从独立网页贯通到有效 Bundle；来源原件、正文、图片及引用可访问，未知元数据不编造。
- 图片不是入库必需项；原本无图的 PDF 不因缺少图片而失败。有图片引用时仍须验证对应资源可访问。此项为 2026-09-22 grill Q1 已确认要求，尚未据此验证实现。
- 阶段 1 不强制 AI 审核；原件一致、正文非空、元数据合法、引用完整等程序校验通过后，由 Core 发布。Codex 不可用不阻止合法 Bundle 入库，Runtime 能力验证单独保留，不在默认入库链路附加 AI 审核调用（本轮 Q4）。
- 无 Plan 的 Source 可以入库并被查看；没有上传后规划／全文翻译的遗留触发。
- 重复确认／请求不会重复发布或复制 Source；解析失败可重试，已有合法产物保留。身份相同原件按既有复用规则处理。
- 相同原件尚有未完成入库任务时，重复添加应识别并引导回原任务，不再次解析；需要重提时走明确的“重新提交”操作，不能通过新建 Inbox 绕过提示（本轮 Q3）。
- 远端受理情况未知时不自动重传；已有任务号时优先查询并续接原任务。无法查明时允许用户在看到“上次提交结果未知，重新提交可能重复解析”的说明后，明确选择“重新提交”。此项为 2026-09-22 grill Q2 已确认要求，尚未据此验证实现。
- 文档入库与专题关联分开报告：Bundle 发布后即使目标 Topic 挂接失败，仍可从 Inbox 状态或来源入口查看；任务显示关联待恢复，重试只补关联。Topic 视图引用统一 Source Library，关系只保存一次，不复制 Bundle 或在文档 metadata 中另维护关系副本。
- 无效结果不发布；取消立即禁止该 attempt 提交，迟到结果不能落成正式资产；中断后从已确认业务断点恢复。
- 并发写入者被拒绝；共用流程能以 fixture 脱离浏览器运行，并有真实参考解析验证。外发和提交规则不能只靠提示词。

## Spec 承接

用户已批准 [4 张实施票](../../../.scratch/focus-v02-stage1/README.md)：先统一 Parser、完成共享后端和续接／真实运行，再接入最小网页；不按每张票都含 UI 拆分，不另建防御性或验收任务。

阶段 0 Q1–Q12 已收敛确认、身份复用、分步结果、续接、取消、冲突和唯一写入方规则；本地 spec 将其整理为用户故事、实施决定与验收场景。主测试边界为共享 Application 单篇入库 Interface，配真实 Core 与可控外部适配器；少量 Host／浏览器验证接入。既有证据见验收记录；本轮补充的无图入库、显式重提、未完成任务复用及无 AI 审核入库须另行验证。

不含博客、问答、备注、精读、批量和完整 Topic CRUD；这些不得成为入库成功的前置条件。
