# 阶段 1：单篇统一入库

状态：已依据阶段 0 确认决策生成 [本地实施 spec](../../../.scratch/focus-v02-stage1/spec.md)，主测试边界已获用户确认；尚未实施或验收。依据：总计划 §1、§3–5、P1／P2。依赖：阶段 0 的已确认边界及 spec 所列实测门槛。

## 用户结果与范围

用户创建或选择最小 Topic，将一份 PDF 放入 Inbox，检查目标和处理说明，明确确认后得到可查看来源的 Parser Bundle。新版入库到此成功，不创建 Reading Plan，不等待全文译文或博客。

统一使用 article-parser，迁入可复用 PDF 解析、规范化、元数据、组装和导出能力，保留已有 HTML 能力；删除旧 paper-parser Skill 和废弃调用入口，不保留旧名称兼容壳。通过共享 Application 编排并由 Core 校验发布。将必要 Core 能力抽入正常 Python 包、建立最小 Parser／Runtime 接口和统一方法来源；其余必要包装只能单向调用同一实现。只迁本切面需要的能力。

Core 管稳定 Source 身份、解析 ID、Bundle 版本及 Topic 关系；标题路径不是身份。Inbox 项、确认和失败状态要能恢复；失败或远端仍运行时不能伪造正式 Source。原件及证据按 Bundle 契约保留。

## 验收出口

- 刷新后未确认项目仍待确认，无远端解析或模型外发；确认绑定所选文件及目标，修改输入不会沿用失效授权。
- 一份授权 PDF 从独立网页贯通到有效 Bundle；来源原件、正文、图片及引用可访问，未知元数据不编造。
- 无 Plan 的 Source 可以入库并被查看；没有上传后规划／全文翻译的遗留触发。
- 重复确认／请求不会重复发布或复制 Source；解析失败可重试，已有合法产物保留。身份相同原件按既有复用规则处理。
- 文档入库与专题关联分开报告：Bundle 发布后即使目标 Topic 挂接失败，仍可从 Inbox 状态或来源入口查看；任务显示关联待恢复，重试只补关联。Topic 视图引用统一 Source Library，关系只保存一次，不复制 Bundle 或在文档 metadata 中另维护关系副本。
- 无效结果不发布；取消立即禁止该 attempt 提交，迟到结果不能落成正式资产；中断后从已确认业务断点恢复。
- 并发写入者被拒绝；共用流程能以 fixture 脱离浏览器运行，并有真实参考解析验证。外发和提交规则不能只靠提示词。
