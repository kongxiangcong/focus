## 已确认的路线与用户结果

- 用户继续使用同一 FOCUS 界面、Host 和 Knowledge Base，在设置界面选择 Codex 或 DeepSeek Backend；不再交付另一套 DSH 原生 FOCUS 应用。
- DeepSeek 使用官方 Harness SDK 及其配套 Runtime。这里取消的是 DSH 宿主集成路线，不是承诺安装包或执行进程中完全没有 DSH 组件。普通模型 API 直连、让 Codex 改用 DeepSeek provider 均不是本阶段已选路线。
- “和 Codex 一样”指作为 FOCUS 的可选 Agent Backend 接入同一业务能力，不要求两者底层协议相同，也不要求为了本阶段重写当前 Codex App Server 适配器。
- Backend 与 FOCUS 功能分离：Backend 只提供不同的 Agent 能力。用户因 Codex 会员或 DeepSeek 使用条件选择 Backend，获得相同的 FOCUS 功能；不为两种 Backend 分别开发业务功能。协议、认证与能力映射由适配层处理，共同业务契约不分叉。
- 后续围绕本文进行需求讨论、形成 spec 并拆票；不继续原阶段 6 的 grill，不把其未回答的问题作为本阶段默认决策。

## 共享架构与状态权威

接入方向为：现有 FOCUS UI／设置 → FOCUS Host → Backend Adapter → 所选 SDK／Runtime。Backend 的工具调用回到同一 Application／Core；业务流程、Methods、schema、校验器和结果格式只有一套。

Core 仍是 Source、Bundle、Blog、Reading Notes、Plan、Cursor 等资产的唯一权威；Application 管理业务 Run／Step／attempt 及提交资格。SDK 会话记录、模型上下文与运行事件属于 Host／Runtime，不承担业务断点或阅读位置权威。一个 AI attempt 只有一个模型—工具循环，不再让另一套 DSH Host 编排相同业务。

FOCUS Discussion 是 FOCUS 自己管理的、绑定 Source 的用户讨论，与 Runtime 原生 Session 分离。切换 Backend 后仍查看和继续同一讨论；不为每个 Backend 保留一份独立讨论，也不因切回旧 Backend 恢复另一条分支。FOCUS 完整保留用户可见讨论；统一以近期对话、较早讨论摘要与必要来源上下文接续模型。压缩不删除原讨论，不自动生成 Reading Notes；不同模型的回答不保证一致。

“清除本篇讨论与笔记”删除该 Source 的全部 FOCUS Discussions、派生摘要和 Reading Notes，并使关联运行上下文失效；保留 Plan、Cursor、博客与独立的 Reading Progress Entries。该 Source 有活动任务时禁止清除；操作必须说明实际删除范围、不可撤销及保留内容并要求确认，同时清除 Notes 恢复副本，不能由单条笔记撤销恢复已清除内容。清除／删除 Notes 的操作按钮仅出现在知识库主页的 Bundle 卡片，不在阅读界面提供。Notes 仍是 Source 级资产，不按讨论分配所有权。

沿用现有 [Backend 接口](../../../host/backends/base.py) 作为讨论基线。[ADR 0007](../../adr/0007-selectable-agent-backends.md) 已按本轮决策修订切换时的讨论语义：保留统一讨论、隔离原生会话键及迟到消息。该修订是目标决策，不代表代码已实现；不放宽为运行中热切换。

## 设置中的 Backend 选择

已确认设置界面提供 Backend 选择。以下为已确认边界，具体字段和布局在 spec 中细化：

- 区分 Backend、模型和凭据；显示当前选择，以及未安装、未配置、不可用或可用等真实状态。只有通过对应预检查的配置才能用于任务；失败不伪装成功、不静默切换到另一个付费服务。
- 凭据由后端管理，不进入 Knowledge Base 业务资产、浏览器持久化或诊断明文。SDK 使用 FOCUS 管理的配置和运行目录，不隐式借用用户个人 DSH profile／聊天记录。
- 一个默认 Backend 统一驱动讨论、博客、Plan、翻译及其他 AI 任务；首版不增加逐 Source／逐任务／逐步骤路由。解析服务仍走既有解析流程。配置按本机应用用户保存，跨 Knowledge Base 共用；凭据与运行配置保存在应用配置区，不随知识库携带。
- Backend 只能在设置页修改，不提供讨论页快捷切换。FOCUS 有任务运行（含仍在调度的批次）时禁止修改 Backend／模型配置；先等待完成或明确停止。Reload 等同于刷新网页，按钮与用户手动刷新走相同的配置生效路径，不要求用户重启 Host。
- 保存后、尚未刷新时，允许继续以当前生效配置启动任务。已保存配置与当前生效配置不同时，页面右下角显示常驻状态弹窗“配置更改，需要刷新页面”，不因超时自动消失；刷新后生效并消除差异。若用户把配置改回当前生效值，提示立即消失，无需刷新。是否有差异依据最终配置值，不依据修改次数或一次性的 changed 标记。
- 不做执行中热切换，已启动 attempt 的模型和 Backend 来源可追溯。若保存新配置后又启动旧配置任务，并于运行中刷新，页面正常恢复任务显示，但不应用新配置、不取消任务；显示“任务运行中，完成后请刷新以应用配置”。任务结束后再次刷新才应用，不在结束时自动切换。
- 同一 Host 只有一份当前生效配置；任一页面在空闲时刷新并成功应用后，其他页面同步显示新的 Backend，后续任务统一使用它，不允许按标签页保留不同生效配置。
- 切换后保留同一 FOCUS Discussion、业务资产与阅读位置。新 Backend 通过统一讨论上下文继续，不能复用其他 Runtime 的原生 session ID，或宣称原生上下文无损迁移。
- 首次启用默认同时安装 Codex 与 DeepSeek 依赖；该步骤只安装，不自动发起账号登录或模型任务。两套依赖分别报告安装结果，某套失败可重试，不阻塞另一套已经安装且认证可用的 Backend。用户随后在设置页明确选择 Backend；提供各 Backend 经过验证的默认模型及已验证模型选择，不要求填写任意模型名。
- Codex 使用 ChatGPT／Codex 登录，直接共用电脑上已有的个人 Codex 登录，不另建 FOCUS 专属登录状态。设置页选择 Codex 时通过实际所用 Runtime 检查共享登录信息，未登录则提供浏览器授权入口，并在认证完成后复核状态。不得因环境中存在 API Key 而隐式改变认证或计费路径；共用认证不授权修改个人模型／工具配置或读取个人聊天。参见 [Codex 登录调研](../../../research/codex-login-for-focus.md)。
- 批次明确停止后，用户可修改设置并刷新页面，再显式恢复／重试：剩余文档与失败项的未完成步骤使用新 Backend 创建新 attempt，已合法完成的步骤和资产复用，不重做已完成文档，不要求切回旧 Backend。刷新本身不自动恢复或重放批次。

### Backend 连通性检查（2026-09-26 补充）

设置页选择对应 Backend 后，在该选项下方提供“连通性检查”按钮。用户主动点击，检查设置页当前选中的 Backend 及其模型、认证和实际 Runtime 配置；即使它尚未通过刷新成为当前生效 Backend，也可以单独检查。检查不保存或应用配置，不触发刷新，不改变当前任务使用的 Backend，也不清除“配置更改，需要刷新页面”提示。

连通性检查通过对应 Backend 的实际 SDK／Runtime 路径完成最小模型请求，验证启动、认证和请求往返；不能仅凭依赖已安装、存在登录记录或网络地址可达显示成功。不传入私人来源或讨论，不开放业务写入工具，不生成业务资产或追加 FOCUS Discussion。检查成功仅表示本次配置能完成该请求，不代表全部业务能力验收通过。

界面显示未检查、检查中、成功或失败；失败说明可行动的原因，如依赖缺失、未登录／凭据无效、网络失败、额度不足或 Runtime 调用错误，错误内容须去除敏感信息。结果绑定本次检查的配置，选项或相关配置改变后不沿用旧成功结果，迟到结果不能覆盖另一配置的状态。两种 Backend 使用同一套检查交互；不自动重试到其他 Backend，不增加版本号门槛，也不要求用户每次启动任务前手动点击检查。

## SDK 能力与生命周期

FOCUS 不提供“升级到最新 Runtime”，也不绑定特定 Runtime 版本。不以版本号、版本白名单或版本区间作为启动门槛，不强制降级、不自动回退，用户可在外部自行升级当前使用的 Runtime。FOCUS 直接使用所配置的 Runtime；实际启动或协议调用失败时报告真实错误，保留合法资产和可恢复状态，由用户单独修复。版本不感知是产品行为要求，不是对所有未来版本兼容的承诺。SDK 包自身的依赖约束与 Runtime 解析路径须在实施前核实，不能继续由 FOCUS 强制锁定旧 Runtime。

Runtime 选择顺序为：用户明确指定的 Runtime → 本机已安装的 Runtime → 缺失时由首次安装流程补齐。设置页显示实际使用路径，不按版本选择，不因启动失败偷偷改用另一份 Runtime。首次启用对两套 Backend 都完成依赖准备；已有可复用安装不重复建立隐藏旧副本。SDK 如何指定运行路径属于技术核查，不改变该产品规则。

调研已找到官方 Python SDK 与 Windows 运行时包，但文档存在、包可安装不等于 FOCUS 集成完成。后续对实际使用的 SDK／Runtime 验证：事件与流式输出、FOCUS 工具执行、审批／用户输入、结构化候选、取消、恢复、上下文管理、资源释放，以及业务所需的检索和图像能力。验收证据可以记录当次实际版本以复现结果，但不得由此建立产品版本门槛；不把主分支文档能力当作本机 Runtime 已支持的证明。

工具权限按任务限定。候选生成任务只获得所需输入和返回候选的能力；问答与备注通过既有 FOCUS 公共工具执行。SDK 默认 profile 或名为 minimal 的 profile 不能代替工具限制验收；须记录模型实际可见和可执行的工具，并验证越界调用被拒绝。能力缺失须在运行前阻止不支持的任务，不绕过共用校验器。

页面刷新／断连本身不取消任务。显式取消、Runtime 崩溃、Host 重启或切换均须阻止已失效 attempt 的迟到提交；保留已合法发布的资产，重试从业务断点产生新 attempt。Runtime 停止、资源释放、日志保留／归档与业务完成分别报告。

[ADR 0014](../../adr/0014-archive-dsh-attempt-sessions.md) 记录的是原 DSH 探针专用 Session 的停止、释放与归档决定；可复用其已验证约束，但不能把 SDK `close()` 当作归档或永久删除。FOCUS Discussion 持续保留，直到用户明确清除；FOCUS 管理的后台详细执行日志从任务终态起保留 7 天，到期自动清理。业务状态与必要提交回执保留，业务资产独立保存。SDK 原生记录可提供的清理保证仍需能力验证，不宣称它已支持同样删除，也不清理无关的个人 Runtime 日志；归档不能算删除。

## 验收出口（Q23 已确认，尚未执行）

- **安装与配置**：首版安装验收面向 Windows x64，允许首次安装联网；无需用户自行安装 Python、Node 或 DSH，无需克隆仓库、启动 DSH Web UI 或安装 FOCUS DSH 插件。Linux 是后续实际使用方向，本阶段不承担 Linux 适配和验收，不因平台名称主动拒绝运行，也不宣称已经支持。验证干净安装、首次配置、依赖缺失及用户外部升级后实际启动／调用失败的可见结果；不验证或新增版本白名单拒绝，不承诺自动修复／回退。用户只使用 Codex 时，DeepSeek 未配置不应阻塞该路径。
- **共同业务契约**：Codex 与 DeepSeek 经同一 Application 跑业务契约套件；核对资产、引用、来源隔离、Notes、Cursor、幂等、失败重试和取消。既有阶段 2D 证据不能代替 SDK 接入证据。
- **设置与会话**：浏览器实际完成选择、预检查、生效、持久化和切回；验证运行中选择、排队任务、历史讨论、新建讨论和 Source 绑定；原生会话键、凭据与迟到事件不会串入另一 Backend。
- **连通性检查**：分别选择 Codex／DeepSeek 并主动检查，验证真实最小请求的成功与失败、配置改变后结果失效及迟到结果隔离；检查尚未生效的 Backend 不切换当前 Backend，不写业务资产，不替代完整业务验收。
- **本轮关键边界**：两种 Backend 分别验证真实 Runtime 与浏览器完整流程；覆盖 Codex 共享登录及未登录授权、配置改回时提示消失、运行中刷新后再次刷新、多页面同步、切换后接续同一讨论、批次已完成项不重做，以及仅在知识库主页 Bundle 卡片确认清除讨论与 Notes。清除须验证恢复副本一并删除、上下文失效及 Plan／Cursor／博客／Reading Progress Entries 保留。
- **完整业务场景**：分别在真实 Runtime 下跑通适用的阶段 1–5 流程，并记录 UI 状态与产物。包括博客、问答／显式 Notes、Plan 与全文准备、阅读推进，以及批量的失败／取消恢复；不能只验证聊天回复或单次 JSON 请求。
- **正式支持门槛**：阶段 6B 正式完成要求 DeepSeek 覆盖全部已确认 AI 场景。开发中可有明确标记的实验入口，未通过能力在执行前阻止；这只是未完成状态，不形成两套长期不同的 FOCUS 功能，也不静默改用另一付费服务。
- **输出质量**：沿用阶段 5 的共同校验与警告标准。结构、图片、引用等可判定错误阻塞发布；无法可靠自动判定的解释深度等保留明确警告，不新增人工质量审批。不要求生成正文相同，不宣称两个 Backend 内容水平等价。
- **运行退出与回退**：取消、崩溃、Host 重启、切换后的提交资格与清理分别可验证；配置或 SDK 出错时，保留合法产物和可恢复状态。用户显式切回可用 Codex 后，保留原讨论与知识库，在隔离的 Runtime 会话／新 attempt 中继续；不自动重放已完成任务。

分别记录确定性／fixture、Host 集成、浏览器和真实 Runtime 证据。未验证项标为待验收，不因 SDK 已发布或原 DSH 路径曾验证而判通过。

## 第一轮结论（2026-09-26）

- Q1–Q3：同意完整功能门槛、统一 AI 默认及本机应用用户级配置。
- Q4：否决按 Backend 分开保存讨论；FOCUS Discussion 与 Backend 无关，切换不影响讨论。
- Q5：同意 Windows x64 首版验收和首次安装联网；Linux 后续会使用，当前不承担适配，不主动拒绝。
- Q6：同意讨论持续保留至用户清除，后台执行日志有限期保留；具体清理保证待核实。

## 后续技术验证（不重新作为产品待决问题）

1. 核实 SDK 的 Runtime 路径指定与依赖约束，按已确认顺序解析实际 Runtime，移除 FOCUS 的精确版本门槛。

## 最终共识摘要

- FOCUS 功能、讨论、业务资产与校验只有一套；Backend 只替换 Agent 能力，Core 保持唯一业务权威。
- 本机应用用户级设置统一驱动 AI 任务。设置页保存，空闲时刷新生效；刷新前允许旧配置任务，差异提示常驻，改回则消失。运行中禁止改设置，刷新不取消任务也不应用待生效配置；各页面共用 Host 生效配置。
- 首次准备两套依赖，分别报告失败；Codex 共用个人登录，未登录时在设置页提供浏览器授权。Runtime 优先显式指定、其次复用本机安装、缺失才补齐，不绑定版本、不提供升级入口。
- 讨论跨 Backend 延续；停止批次并切换后，显式恢复只处理未完成工作。知识库主页 Bundle 卡片可确认清除本篇全部讨论与 Notes，含恢复副本且不可撤销，保留阅读位置等既有指定资产。
- FOCUS 后台详细日志终态后保留 7 天；首版验收 Windows x64，Linux 不主动拒绝但当前不承担适配；两种 Backend 分别通过完整业务与浏览器验收才算阶段完成。

## 第二轮结论（2026-09-26）

- Q7：同意统一讨论上下文压缩，完整保留可见讨论；不自动生成 Notes。
- Q8：Backend 入口仅在设置页；有任务运行时不可修改，修改后由用户 Reload 才生效。本决定取代上一轮“不增加已保存未生效设置”的建议。
- Q9：首次启用默认同时安装两套 Backend 依赖，取代上一轮按所选 Backend 单独安装的建议。
- Q10：同意显式选择和已验证默认模型；Codex 必须走 Codex／ChatGPT 登录，设置页检查状态并提供浏览器授权入口，首次安装不自动登录。已完成官方文档和本地固定 `0.154.0` SDK 登录接口核查，详见登录调研；尚未真实授权或模型验收。
- Q11：清除讨论包含删除 Notes、所选讨论和派生摘要并使运行上下文失效；保留 Plan、Cursor 和博客，说明范围并确认。具体范围已由第三轮 Q15 收敛。

## 第三轮结论（2026-09-26）

- Q12：Reload 就是刷新网页；刷新前允许旧配置启动任务。右下角常驻“配置更改，需要刷新页面”，改回当前生效配置则立即消失。本决定取代“待刷新时阻止新任务”的建议。
- Q13：停止批次、改设置并刷新后，显式恢复／重试使用新 Backend；已完成文档不重做。
- Q14：直接共用个人 Codex 登录，否决单独建立 FOCUS 登录状态。
- Q15：同意 Source 级清除全部讨论、摘要、Notes，保留 Plan、Cursor、博客与 Reading Progress Entries；清除／删除 Notes 按钮只在知识库主页 Bundle 卡片出现，不放在阅读界面。
- Q16：默认安装两套依赖；部分失败独立报告、独立重试，不阻塞另一套已可用 Backend。

## 第四轮结论（2026-09-26）

- Q17：运行中刷新正常恢复页面与任务，但不应用待生效配置、不取消任务；任务结束后再次刷新才生效，并显示相应提示。
- Q18：同一 Host 只有一份生效配置；任一页面成功应用后，其他页面同步，后续任务统一使用它。
- Q19：Source 有活动任务时禁止清除；确认后不可撤销，同时清除 Notes 恢复副本，不允许编辑撤销恢复已清除内容。
- Q20：FOCUS 后台详细日志自任务终态保留 7 天，到期自动清理；业务状态和必要回执保留，SDK 原生日志清理另行验证。
- Q21：不提供 Runtime 升级入口，也不绑定特定版本；用户可自行升级，FOCUS 不设版本门槛，实际启动出错后由用户单独修复。否决随 FOCUS 固定 Runtime 和自动回退的建议。

## 第五轮结论（2026-09-26）

- Q22：同意用户指定 Runtime 优先，其次复用本机安装，缺失才由首次流程补齐；设置页显示实际路径，不按版本选择，不静默替换 Runtime。
- Q23：同意共同业务契约与两种 Backend 分别进行真实 Runtime、浏览器完整验收，纳入本轮设置、登录、刷新、批次恢复及清除边界。Q1–Q23 产品决策收敛，技术未验证项仍保留待验收。

## 当前实现差距（2026-09-26 静态核查）

- `host/service.py` 当前切换会归档 Host Session 并新建，讨论入口随之重置；不满足统一讨论目标。
- 聊天按当前 Backend 创建回合；reading/progress Runtime 在 Host 启动时固定，博客仍使用缓存的 CodexBlogRuntime。当前设置不能代表所有 AI 任务已统一切换。
- 当前切换检查仅覆盖聊天主 worker/run；后台业务与批量任务仍需共同约束。
- `selectedBackend` 当前保存在绑定 workspace 的 Host 数据库，尚非本轮确定的应用用户级配置。
- `host/runtime.py` 当前默认使用 Python 环境内捆绑 Runtime，不查找系统 PATH；显式 `--codex-bin`／`FOCUS_CODEX_BIN` 可覆盖。`host/backends/__init__.py` 要求版本输出精确等于 `codex-cli 0.154.0`，`host/requirements.txt` 固定依赖版本；这些限制与 Q21 冲突，后续需移除 FOCUS 的版本绑定并落实可解释的 Runtime 解析规则。
- `host/backends/codex.py` 当前发现 `OPENAI_API_KEY` 会主动调用 API Key 登录；不符合本轮只用 Codex 登录的要求。当前也未提供完整的设置页登录与 Reload 生效流程。
