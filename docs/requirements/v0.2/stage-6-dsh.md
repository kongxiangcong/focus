## 用户结果与范围

用户安装原生 FOCUS 插件即可进入知识库、处理 Inbox、查看博客、整篇问答／Notes 及单 Chunk 精读；入口不要求先开聊天。接入 DSH 原生导航、Slots／Remote、Session、任务和插件生命周期。

第一轮 Q1 已确认：完整承接阶段 1–5 已确认的业务能力，包括混合批量、Topic／Source 管理、失败重试、单项取消与整批停止；必需操作和业务规则保持一致，正式发布依赖阶段 5 验收通过。UI 风格和主题须与当前 FOCUS 一致，后续单独拆出主题风格与 UI 视角匹配 ticket；具体装配与布局待后续澄清。

第一轮 Q2 经场景澄清后已确认：在同一 DSH 宿主内，再次打开同一 Reading Source 时默认恢复该文章最近的讨论，并提供“新建讨论”。每段讨论固定属于该 Source，不因打开其他文章而改变绑定；仅打开文章不启动模型。讨论历史由宿主保存，与 Knowledge Base 中的 Reading Notes 和阅读位置分开，也不同于后台生成任务的专用 attempt Session；不扩展为跨宿主聊天迁移。

第一轮 Q3 已确认：交付面向已安装兼容 DSH 的干净机器。通过受支持的安装流程准备 FOCUS 及 worker 依赖，无需克隆仓库或手动组装开发环境；首次使用只需选择知识库并配置必要凭据。具体打包与依赖准备方式待确定。

共享组件与 View Model 由 DSH 装配；业务经受管理 worker 调用同一个 Application，Methods／schema／校验器同版本。原生任务组件展示或触发业务 Run，不复制其状态机；不通过 iframe 包旧站点。

部署范围沿用阶段 2D 于 2026-09-25 确认的决定：仅本机部署，不包含跨机器部署。Remote 指本机页面与 DSH 服务端之间的调用通道；连接重建须恢复业务状态查询，页面刷新或断连本身不取消业务任务，显式取消和执行端失效仍须阻止非法迟到提交。

阶段 5 Q19 已确定新版业务数据目录为 `knowledge-base/`，不迁移旧数据。本阶段停机接管面向已由新版建立的同一知识库，不恢复旧 `workspace/` 目录兼容入口；参见 ADR 0017。

## 验收出口

- 干净环境 build／pack／install／boot 和升级／卸载可验证，发布包标记 FOCUS 与 DSH 兼容基线。
- 两种 Host 跑同一确定性业务套件，比较规范化资产、引用、失败状态、备注和游标。第一轮 Q4 已确认：真实模型分别验证完整流程和产物合规，沿用阶段 5 的共同校验规则与警告标准；结构、图片、引用等可判定错误阻塞发布，无法可靠自动判定的解释深度等保留明确警告，不新增人工质量审批。不要求生成正文相同，也不宣称两种 Runtime 内容水平等价。
- 原生 Session、聊天、连接重建与业务 Source 绑定明确；新会话可读取可移植业务信息，不盗用其他 Runtime 的 session ID。
- 任务取消、断连、worker 崩溃、插件卸载都不接收非法迟到提交；再次启动从合法业务断点恢复。
- 兼容新 schema 的 Host 停机接管完成版本检查、停止／完成任务、释放旧写入权和获取新独占权；资产可继续使用而无需重新解析。第二写入者被拒绝。
- 移除 DSH 集成后 Standalone 仍正常构建／运行；不强迫独立版用户安装 DSH，不启动第二 Agent harness。
