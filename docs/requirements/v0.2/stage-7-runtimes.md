# 阶段 7：Runtime 扩展（已跳过）

状态：已跳过。2026-09-26 用户要求以阶段 6B 为主，仅保留真正必要的新增需求，无独立必要项则跳过阶段 7。对照 [阶段 6B 已确认需求](stage-6b-sdk-backends.md)、[spec](../../../.scratch/focus-v02-stage6b/spec.md) 与 [发布验收票](../../../.scratch/focus-v02-stage6b/issues/05-release-evidence.md)，本阶段的公共要求已由 6B 承接，剩余适配器没有已确认的当前使用需求，不再单独 grill、生成 spec 或拆实施票。

## 与阶段 6B 的覆盖核对

| 原阶段 7 要求 | 当前归属 |
| --- | --- |
| 区分 Backend、Runtime、模型、认证及模型—工具循环所有权 | 6B spec 的唯一业务权威、适配边界与设置要求 |
| 工具限制、图像、流式、结果契约和能力不足时阻止任务 | 6B SDK 能力验证与共同业务验收 |
| 来源隔离、输出／引用校验、幂等与内容质量 | 6B 全业务验收，沿用阶段 5 校验与警告标准 |
| 空闲切换、运行中先停止、隔离凭据／原生会话键／迟到事件 | 6B 保存后刷新生效、统一讨论及批次恢复规则；以 6B 的具体语义为准 |
| 取消后的 Runtime 状态、提交资格与合法产物保留 | 6B 生命周期、退出与恢复验收；停止、释放与业务完成分别报告 |
| 记录版本与认证、区分 fixture／Host／浏览器／真实 Runtime 证据 | 6B 验收记录；记录版本不构成版本门槛 |
| “部分可运行”与“完整支持”的区别 | 6B 已确定正式支持覆盖全部已确认 AI 场景，实验能力不足属于未完成状态 |

上述覆盖指需求与验收责任已有归属，不表示 6B 已实现或验收通过。Codex／DeepSeek 的剩余工作继续在 6B 完成；不另建能力矩阵产品或重复验收阶段，已有分层证据中记录实际配置、能力及未验证项即可。

## 保留为未来候选

OpenAI 独立适配器、Pi、WorkBuddy 是原计划唯一尚未被 6B 覆盖的交付增量；当前没有必须依赖它们才能满足的已确认业务需求，因此退出本轮交付范围，也不作为 v0.2 发布条件。保留候选名称不表示已接入、已授权或承诺后续实现。

以后用户提出 Codex／DeepSeek 无法满足的具体需求时，再针对一个候选重新立项，核实接口、认证及工具循环所有权，复用 6B 的共同业务契约和验收。届时仍不能用 CodeBuddy 替代 WorkBuddy，或用旧 DSH 探针／fake SDK 代替真实接入证据。

跳过本阶段不改变 Core／Application 单一权威，不引入跨 Runtime 原生上下文无损迁移或自动切换付费服务，也不删除既有代码和历史证据。
