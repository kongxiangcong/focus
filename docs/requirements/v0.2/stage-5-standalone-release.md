# 阶段 5：独立网页版能力补齐、知识库初始化与发布

状态：2026-09-26 Q1–Q19、最终共识及最高测试边界均已确认，grill 已定稿；[spec](../../../.scratch/focus-v02-stage5/spec.md) 与用户批准的 [六张实施票](../../../.scratch/focus-v02-stage5/README.md) 已发布为 ready-for-agent。原拆票 01、02 按用户要求合并，其他范围保持不变并重新编号。本记录不是实施或发布验收声明。2026-09-25 合并为一个阶段，2026-09-26 按 Q19 将旧数据迁移改为空知识库初始化；统一讨论输入格式、批量处理、专题与文档管理、初始化与发布。依据：总计划 §1、P3、§7–8 及本轮已确认修订。

## 本阶段目标

在阶段 1–4 的单篇流程基础上补齐独立网页版的完整使用闭环，从空的 `knowledge-base/` 知识库开始并达到发布条件。以下四个主题共同组成一个阶段，统一 grilling、形成一份阶段 spec，再按真实依赖拆分纵向 tickets；各主题保留独立验收条件。

继承阶段索引中的 Core／Application／Methods 单一权威、确认、幂等、取消及分层证据要求。统一发布出口需要全部主题的验收证据，不以合并文档代表能力已实现或已验证。

## 依赖与交付顺序

- 输入格式完整场景依赖阶段 1–4；阶段 1 已明确 PDF，本阶段补齐 HTML。
- 批量处理依赖阶段 1、2 的单篇路径；PDF／HTML 混合批量验收还需本阶段的格式覆盖。
- 管理能力依赖阶段 1、3；完整资产关系验收需阶段 2、4，并统一讨论运行中批量任务与管理操作的交互。
- 空知识库初始化及完整新流程发布验收在格式、批量、管理能力验证后完成，并需要阶段 2D 的出口证据；旧 schema 盘点、转换及迁移 dry-run 不再是阶段 5 交付或阻塞条件。
- 各项按实际依赖推进，不要求机械串行。阶段 6 的正式发布依赖本阶段的稳定业务出口；同 schema 停机切换宿主仍由阶段 6 验证。

## 交付主题与分项验收

### 输入格式与解析能力

在同一 Inbox／Application 路径补齐 PDF 和用户选择的单文件 HTML，均发布同一契约 Bundle，并走通博客、整篇问答、独立备注和可选精读。格式差异留在解析适配和证据规则，不复制业务状态机。

现有 HTML Parser 可复用，但方法原先的 PDF-only 前置条件必须在共用 article-blog 方法中消解。非论文文章没有公式、实验或表格时依据真实内容解释，不强塞论文模板。

第一轮 Q1–Q3 已确认：独立网页正式入口为 PDF 与用户保存的单文件 HTML；直接 URL 输入不计入本阶段交付，不新增网页采集能力。现有 Markdown 导入保留回归，不新增正式入口。2026-09-26 用户进一步确定：PDF 保留远端 MinerU，HTML 改为本地 Mozilla Readability 与图片封装；不考虑本地 MinerU 部署。

Reading Blog 对两种来源均为必需产物；Value Analysis 按内容适用性而非文件格式判断，涉及硬件架构、DSE、编译器、仿真器或性能建模且有足够原文依据时生成，否则说明不适用理由。页面统一称“架构价值分析”；非论文材料解释工程设计与边界，不虚构实验或研究贡献。此决定扩展 ADR 0013 的来源适用范围，保留其条件产物、失败重试及合并 HTML 规则。

#### 验收出口

- 两种格式各有真实 Parser＋Runtime 及浏览器完整场景，覆盖图片、引用和内容质量警告；本地 Markdown 或 fixture 不能替代。第一轮 Q6 确认：可判定的结构、图片和引用错误阻塞发布；解释深度等不可可靠自动判定项以明确警告呈现，不新增人工核查或审批。
- HTML 无效文档、资源损坏／缺失及解析失败给出明确结果；不绕过访问控制或增加发布平台专用采集器。Q13 确认：无图文章合法；文章文字没有“如图”等显式图片引用、图片编号或图注也合法，不套用论文格式门槛。需保留的正文图片资源若确实缺失或不可解码，仍阻塞发布；“没有文字指图”不等于“缺图”。
- 已发布 Bundle 在各下游步骤均可核查来源；错误只重试对应阶段，不重新规划或重新解析整个流程。
- 记录 PDF 云解析器与 HTML 本地解析组件的准确版本和已验证能力；本地 MinerU 不在本阶段支持范围内，不作为 fallback。
- 保留现有 Markdown 导入的回归边界，不新增其正式 UI 入口，也不扩大为必需解析格式。

Q12 回答未认可新增“所有 HTML 按字节区分快照”的提议，不将其写为已确认决策；沿用当前 ADR 0016 的身份规则，不引入原件替换或 HTML 版本管理功能。

### 批量 Inbox

Q15 已确认：固定流程为“选择／新建 Topic → 选择文件 → 点击‘开始解析并生成博客’”。点击前展示文件清单、Topic 和所用服务，该点击即为确认，不增加二次弹窗，不提供“仅入库”或逐项处理范围配置。确认后逐项进入已有入库与博客流程；博客失败保留已入库来源。批量是多个单篇业务的组织方式，共用确认、发布和重试规则；不要求并行执行或引入通用调度平台。

第二轮 Q7、Q10 修订：上传必须绑定 Topic，一批文件属于同一个 Topic。用户在一个可选择／新建的下拉框中复用已有 Topic 或输入名称新建；名称去首尾空白、忽略大小写后相同即复用同一 Topic。不提供逐文件 Topic 配置；批量上传绑定一个 Topic 不改变 Source 可在后续管理中属于多个 Topic 的领域规则。

第一轮 Q4 已确认：首版串行执行，单项失败后继续后续项；解析成功而博客失败显示部分完成，来源可立即打开，只重试失败博客步骤。认证失效等影响整批的公共故障暂停整批，避免逐项重复失败。

第二轮 Q8 已确认：单项取消仅影响该项；整批停止取消当前 attempt、暂停尚未执行项，保留已提交产物。移除排队项不删除已经注册的 Source。关闭页面不停止后台任务；Host 重启先恢复状态，用户点击继续后恢复处理，已有远端任务先查询而非重新上传。继续仍在原确认范围内时不重复弹确认；未知远端受理结果仍遵守 ADR 0012。

#### 验收出口

- 未选中或未确认的项不外发；确认后的新增／替换文件不自动获得授权。
- 每项显示待处理、处理中、已完成／失败／取消及所在业务阶段；部分成功不伪装成全部成功。
- 一项失败不破坏成功项的 Bundle／Blog；只重试失败或未提交步骤，重复文件复用稳定 Source。
- 刷新／重启后可识别已提交项和剩余项，不盲目重放远端上传或正式写入。
- 单项及整批停止的作用范围明确，取消 attempt 的迟到结果不提交；已提交合法产物保留。
- 每份成功文档都可独立打开来源和后续阅读，不以整批完成作为访问条件。

Q16 已确认：开始后固定该批 Topic 和文件清单，不允许处理中修改目标、替换文件或追加文件；新文件另起一批，可继续选择同一 Topic。保留取消、移除排队项及重试，不扩大原确认授权范围。

### 专题与文档管理

补齐最小 Topic 创建／选择之外的 Topic CRUD、Source 归属维护与文档管理。Topic 只组织 Source ID；一份 Source 的 Bundle、Blog、Notes、Plan 和 Cursor 始终只有一套权威资产。

在现有 SourceLibrary 和知识库 UI 上增量扩展，明确区分“移出专题”和“删除来源”。继续展示真实的入库、博客与阅读状态，不再用是否有 Plan 作为一份 Source 能否使用的条件。

第一轮 Q5 已确认：最小文档编辑范围为纠正 Source Title 元数据、调整 Topic 归属与专题内顺序、移出专题及删除来源。纠正标题不改变 Source ID；不新增展示别名、原件替换或解析正文编辑器。

第二轮 Q9 修订：正在生成博客时不能改标题、移出 Topic 或删除 Source；不引入上一轮建议的复杂按对象协调机制，其他运行中写操作继续遵守既有保护规则。

第二轮 Q10 已确认：创建时复用规范化后同名 Topic；重命名到另一已有名称时拒绝，不自动合并。支持专题内 Source 排序，不新增 Topic 之间的手工排序。删除 Topic 仅删除专题及其关系，Source 和阅读资产保留；无专题来源仍在“全部来源”中可访问。

第二轮 Q11 已确认：Source 沿用物理删除，不新增回收站。确认时展示受影响 Topic 及 Bundle、Blog、Notes、Plan、阅读进度的范围；清理关联引用，历史聊天保留，已删来源引用显示“来源已删除”且不能继续调用。已取消 attempt 的迟到结果不得恢复来源资产。

#### 验收出口

- 同一 Source 可以属于多个 Topic，编辑名称／归属不改变身份、复制资产或重置阅读。
- Topic 重命名、排序及删除后的 Source 保留规则明确；源身份和目录名不随展示标题误变。
- 从 Topic 移除只改变关系；删除 Source 前让用户理解影响范围，操作后无悬空 Topic、Notes、Blog、Plan 或 Cursor 引用。
- 有运行中任务时，管理操作被适当阻止或按明确规则取消，迟到结果不能复活已删除来源。
- 操作失败恢复一致状态；刷新后管理结果与 Core 一致，UI 不保存第二套关系或游标。

### 空知识库初始化与独立版发布

Q19 已确认：FOCUS 从空知识库重新开始，数据根目录统一命名为 `knowledge-base/`，不再使用 `workspace/` 作为新版数据目录名。旧 Source、Topic、Bundle、Blog、Notes、Plan、译文及阅读进度全部不迁移；需要的文章由用户通过新流程重新上传。旧目录暂不参与新版运行，本次需求整理不移动、重命名或删除实际旧数据。

此决定替代 Q14 的迁移交付范围和 Q18 的“迁移与回退”验收行，取消旧 schema 转换、迁移 dry-run、历史备注展示及旧资产映射。其他功能与失败恢复验收不变。决策依据见 [ADR 0017](../../adr/0017-start-fresh-in-knowledge-base.md)。

新目录仍由 Core／Application 管理唯一一套 Source Library、Topic、Inbox、Notes、Plan 和 Cursor；目录改名不产生第二份资产权威。新版初始化、配置默认值、启动入口和使用说明统一指向 `knowledge-base/`，不自动导入旧目录，也不以旧 `workspace/` 作为 fallback。已存在的新知识库重启时继续使用，不因“从零开始”的发布决定而被清空。

阶段 6 仍验证兼容新 schema 的本机停机接管，沿用同一新知识库且无需重新解析；取消旧数据迁移不取消这项能力。

#### 验收出口

- 无旧目录时可初始化空 `knowledge-base/` 并完成新流程；旧 `workspace/` 存在时也不读取、导入、修改或依赖其资产。
- 默认路径、初始化与重启均落到同一 `knowledge-base/`；重启不清空已新增的 Source、Topic、Notes 或阅读进度，不创建第二份业务数据目录。私人知识库资产不得进入版本控制。
- 入库不依赖 Plan 或翻译；进入精读仍按阶段 4 与 ADR 0010，在当前 Source 的全 Plan 初始化准备完成后开始阅读。
- 部分失败可恢复／重跑，不产生双份权威状态；保护新知识库已提交资产，不要求旧版本读取新 schema。
- 独立网页完成 PDF／HTML、批量、博客、问答／备注、显式进入并完成全 Plan 准备后的精读、管理及失败恢复的真实验收；无需安装 DSH。
- 发布说明记录版本、已验证能力和未通过项；开发辅助 Skills 与产品 Methods 的边界清楚。DSH 探针持续回归，防止公共接口退化为独立 Host 专用。

## 统一发布出口

四个主题的验收条件全部纳入阶段 5 出口，从空 `knowledge-base/` 串联验证多格式入库、批量处理、Topic 归属、博客、问答／备注、精读及管理，并覆盖失败恢复与重启后的同一流程。真实 Parser／Runtime 及浏览器完整场景不能由 fixture 替代。发布报告区分“流程与产物校验通过”和“内容质量尚未证实”：不可可靠自动判定的深度与证据质量保留警告，不新增人工审批，也不声称质量已证实；可判定的校验错误和其他必需验收未通过项仍阻塞阶段发布。独立网页版无需安装 DSH，阶段 2D 探针持续回归。

## 最低发布验收集（Q18 确认，Q19 修订初始化范围）

| 场景 | 必须证明 |
| --- | --- |
| PDF、带图 HTML、无图 HTML | 各自走通真实解析、博客、问答与备注；HTML 图片不要求编号或文字指图 |
| PDF／HTML 混合批量 | 一个 Topic、串行处理、单项失败后继续、成功项立即可用 |
| 停止与恢复 | 单项取消、整批停止、Host 重启继续、无重复提交或迟到发布 |
| 专题与来源管理 | 同名复用、排序、多专题共享、运行中禁用、删除后引用完整 |
| 精读 | 全 Plan 准备完成后进入，推进与已有资产不受管理操作误改 |
| 空知识库初始化与重启 | 空 `knowledge-base/` 完成新流程；旧目录不参与运行；重启继续使用同一知识库且保留新增资产 |

必需功能未通过就阻塞发布；无法自动证实的解释深度明确标注，不增加人工质量审批。既定 Stage 2D 出口要求保持不变。样例类别已确定，实施时记录具体样例、版本与证据，不以历史测试结果代替当前验收。

## 范围外

- 不交付直接 URL 输入、新 Markdown UI 入口或本地 MinerU 部署。
- 不新增展示别名、原件替换、解析正文编辑器或人工内容质量审批。
- 不迁移任何旧知识库资产，不交付旧 schema 转换、迁移 dry-run、历史备注展示或转换入口。
- 不引入通用批量调度平台、多解析器竞速或平台抓取。
- 不增加并发 SLA、后台集群、跨宿主同时写入或新的解析／博客实现。
- 不做资产复制式专题目录、多用户共享或知识图谱。
- 不承诺任意历史版本自动升级、双向 schema 同步、网络盘双写或无损原生聊天迁移。

### 2026-09-26 HTML 路径确定

网页输入为完整 SingleFile HTML；采用 Mozilla Readability 定位正文、本地提取内嵌图片并转换 Markdown，替代 MinerU-HTML。统一 Inbox 声明本地 HTML 解析服务，复用确认、取消、校验和 Core 发布；直接 URL 和浏览器采集仍不在输入范围。原 HTML 保留原始字节，正文图片资源缺失与正文边界不明确时拒绝发布，无图或没有文字指图的文章仍合法；导航、评论、推荐、广告和弹窗按结构移除。参见 ADR-0016。
