## 本阶段交付

本轮事实与未通过项见 [预检查记录](stage-0-precheck.md)。

形成下一阶段能直接实施的边界记录：当前可运行流程及失败项、参考 Parser／Runtime／模型配置、隔离试验目录、旧版本恢复点、首阶段确认与提交规则。首阶段推荐单篇 PDF，Codex 为参考 Runtime 候选；以实际预检查结果定案。

盘点现有私人资产的布局和 schema，记录 Source、原件、备注、Plan、Cursor 与 Topic 关系的保护范围。试验默认使用新建且被忽略的目录和授权样例，不对旧 workspace 做写入或转换。

只收敛单篇入库所需身份与 Bundle 边界、确认范围、Run／Step／attempt 最小语义、提交版本／写入方和取消重试约定。用小样例说明 Source 可以没有 Plan；为博客、备注留明确边界，不在此冻结全部字段或搬迁所有目录。

## 验收出口

- 区分当前测试通过、失败、未测和历史证据；给本轮基线失败指定处理范围，保留可复现命令。

## 已确认的阶段边界

### 第一轮已确认（2026-09-21）

- **确认范围**：完整产品一次明确确认覆盖解析与后续博客，确认时展示服务、用途和处理范围。阶段 1 只确认并执行单篇入库；Bundle 发布即入库成功，不等待博客。问答、精读与 Continue Reading 分别触发，不能沿用入库确认自动推进。
- **重复文档**：相同 PDF 文件内容复用已有 Source 和同一 Bundle 目录；文件改名不改变身份。目标 Topic 不同时增加其对已有 Source 的引用，保留其他 Topic 关系，不复制资产，不触发重新解析。主动重新解析是独立操作，成功后发布新 Bundle 版本；内容不同的 PDF 暂不自动合并为同一作品的新版本。
- **基线失败处理**：旧实验适配器不再需要，删除其适配器及 Host 测试和专用 SDK 替身。技能将改写更新，保留当前技能相关失败记录，不先修旧断言；本轮开发结束后重新运行并刷新失败清单。届时不再对应有效产品要求的无关失败测试直接删除，记录删除依据；仍对应有效要求的失败保留并处理。UTF-8 解码问题尚未归因，不提前认定为技能问题或无关项。历史测试结果仍保留，不将删除测试表述为原问题已修复。

### 第二轮已确认（2026-09-21）

- **样例与参考配置**：采用仓库根目录 `2604.04750v2.pdf`，用户已授权向 MinerU 云解析和现有 Codex 配置发送该样例的必要内容。先预检查并记录实际模型、版本、认证与能力；不通过则报告阻塞，不静默替换服务。
- **隔离与恢复**：试验根目录为 `.scratch/focus-v02-stage0/`，显式区分 `workspace/`、`host-data/` 和 `evidence/`，均受现有忽略规则保护。旧代码恢复 tag 为 `v0.1-pre-v0.2`，指向 `1de307f51c9bd674b8c7efc053e57e5e5b777276`；tag 已本地创建，未推送，不包含当前未提交文档与测试修改。旧资产只读盘点，迁移前停机备份并验证恢复；恢复到独立目录，不覆盖新资产。
- **需求权威**：忽略 v0.1，以 v0.2 总计划、`methods/article-blog/reference/` 下的方法副本和已确认阶段记录为依据。缺失 v0.1 不再构成验收阻塞。
- **续接重试**：失败从当前已完成进展继续，不从头重来。复用合法已提交产物、可恢复的远端任务与断点，仅重新执行未完成部分；同一输入、服务与处理范围内的显式重试沿用原确认。自动重试有限；是否已受理不明时先查询或报告状态，不能盲目重复上传。更换文件、服务或扩大处理范围须重新确认。Run／Step／attempt 边界见第三轮，自动重试上限见第四轮。

### 第三轮已收敛（2026-09-21）

- **断点粒度（Q8）**：用户确认 Run 表示一次业务任务，Step 表示可恢复步骤，attempt 表示步骤的一次执行。每个可恢复步骤保存有效断点；已完成解析就复用结果，已发布 Bundle 就只续接后续步骤。查询原远端任务不算重新执行；无有效断点的未完成部分才重做。
- **取消（Q9）**：用户确认取消永久关闭原 attempt 的提交资格，保留已完成有效断点。用户再次继续时创建新 attempt，从最后有效断点开始；原 attempt 的迟到结果不能自动成为正式资产。
- **展示与存储（Q10）**：用户要求知识库按 Topic 展示，一份文档可以属于多个 Topic，本地不得冗余复制；具体存储方案授权由实现方判断。沿用 ADR 0003：统一 `sources/<source-id>/parser-bundle/` 保存唯一 Bundle，`topics/<topic-id>/topic.yaml` 的有序 Source ID 列表是关系的唯一权威。论文在页面上的 Topic 标签和反向查找从这些关系生成；不在 Source／Bundle metadata 再维护可独立修改的 Topic 副本。首阶段不引入数据库或持久化反向索引，也不整体搬迁目录。
- **分开报告两种结果**：Bundle 经 Core 成功发布即“文档已入库”，不因目标 Topic 挂接失败而撤销或隐藏有效 Source。挂接失败单独显示“目标专题关联待恢复”，Inbox 任务仍未完整完成；重试只补关联，不重做解析。专题视图仅列出已关联 Source，未关联成功的文档仍可从 Inbox 状态和来源入口访问。原 Q10 的整体成功门槛据此细化，不能将关联失败误报为解析失败。

### 第四轮已确认（2026-09-21）

- **提交与写入方（Q11）**：Core 是唯一正式提交入口，提交携带预期版本、请求 ID 和有效写入方身份。版本已变化时保留候选结果、报告冲突，不覆盖当前资产；候选结果不是正式发布产物。同一工作区只允许一个有效写入方，第二个 Host 获取写入权时被拒绝。
- **自动续接上限（Q12）**：暂时性网络错误最多自动续接 2 次，之后保留断点等待用户手动重试。认证失败、结果校验失败直接报告；远端是否受理不明时先查询，无法定位则显示“状态待核对”，不自动重新上传。正常远端进度轮询不属于重新执行步骤。

持久化边界和旧 ADR 的替代范围见 [ADR 0012](../../adr/0012-resume-business-steps-with-guarded-commits.md)。本阶段没有剩余产品选择题；字段结构、锁实现和具体步骤划分由阶段 1 spec 在以上约束内细化。
