# 工作区可迁移性与首次初始化

状态：产品需求已收敛；用户随后取消独立 Windows 发行包，并授权合并实施票。正式规格与三张实施票已发布，本文不是实现或验收通过声明。

日期：2026-10-06。

## 已确认范围

用户同意按以下四步渐进演进现有 FOCUS，不实施完整 DSH 原生工作台或其他完整多宿主工程：

1. 定义完整可迁移用户数据范围，覆盖来源、博客、笔记、计划、阅读进度、FOCUS 讨论和必要业务恢复记录；机器凭据、Runtime 路径和原生执行日志分别管理。
2. 将 Knowledge Base 的稳定身份与存放路径分离，补全库格式兼容检查，以及明确的停机备份、恢复和搬迁流程。
3. 补齐受控写入者接管，并将重新阅读、清除和相关业务恢复规则收回共享 Application／Core。
4. 保持项目程序与用户数据目录独立，整理必要的资源定位，使项目移动或更新后仍可打开本轮新格式工作区；沿用现有本地项目启动方式，不新增发行包交付。

2026-10-06 Q6 修订：按尚无用户的新产品设计，不兼容、不迁移现有 FOCUS 用户记录，也不自动识别旧安装。当前 FOCUS 阅读数据及关联 Host 状态允许在实施时清理，不承担保全与转换要求；清理范围不包含源码、工程文档、凭据及个人 Runtime 配置。四步演进中的搬迁、恢复和后续应用升级能力面向本轮新格式产生的数据。见 [ADR 0020](../adr/0020-portable-workspaces-with-first-run-selection.md)。

## 首次初始化的已确认体验

- 没有知识库路径配置时，进入与当前主题一致的初始化界面，提供“导入工作区”和“新建工作区”。用户先选择知识库位置，再进入工作台。
- 保存成功选择的工作区配置；后续正常启动直接使用，不反复要求选择。
- 初始化提供 Codex 与 DeepSeek 后端选择，每个后端具有“连接检查”和模型下拉入口。
- 只有连接检查确认模型供应商可连接后，才加载该后端实际提供的模型清单，允许用户选择；不能将前端固定模型列表冒充供应商返回的清单。
- 用户可以不执行连接检查，也可以不手选模型，使用所选后端的默认模型进入工作台。进入后可在设置中手动配置。
- 工作台自动保存工作区路径、后端和模型选择；项目目录 `.env` 只承担密钥等环境配置。初始化小字为“API 密钥等配置可在项目目录的 `.env` 文件中填写；Codex 使用已有登录。”
- 初始化应帮助用户快速进入工作台，减少解释、字段和配置步骤；视觉沿用当前主题。

## 第一轮已确认决定

- Q1：导入即原地打开已有工作区并记录路径，不复制数据。工作区包含 Knowledge Base、FOCUS 讨论及阅读进度等完整用户数据；备份恢复是独立操作。
- Q2：新建时选择父目录，默认建立可改名的 `knowledge-base` 子目录；目标已有工作区时提示导入，保留现有文件。
- Q3：应用自动保存路径、后端和模型选项，`.env` 保存密钥等环境配置，Codex 使用已有登录。
- Q4：主动检查失败也可以选择“稍后配置，进入工作台”；显示简短原因，已有内容仍可阅读，需要模型的操作提示到设置完成配置，不自动换后端。
- Q5：设置提供“更换工作区”，复用导入／新建界面，只在没有运行任务时允许操作；不增加多工作区列表、最近记录或并行打开多个库。
- Q6：忽略现有用户安装和记录，不设计旧数据过渡；允许在实施时清理现有 FOCUS 数据。

## 技术核查与后续设计前提

- 当前启动入口在 HTTP 启动前创建知识库并初始化业务服务；实现需要增加未绑定工作区的启动状态，使初始化界面可以先打开，尚未选定目录时不触发业务恢复。
- 本期选择的是运行 FOCUS Host 的本机目录。使用本机文件夹选择能力，并允许手动输入路径；普通浏览器“上传文件夹”不等于持久绑定 Host 目录。
- 导入校验工作区身份与格式兼容性，拒绝非工作区目录或无法支持的格式。保存路径失效时进入重新定位／新建入口，保留原记录供用户辨认，不自动建立替代空库。
- 当前模型列表为前端常量，需要实现真正的模型发现。Codex 使用所选 Runtime 的模型清单，DeepSeek 使用对应供应商模型清单；清单存在不能单独证明每个模型都通过推理。
- 初始化与设置复用后端选择和模型发现逻辑。一次检查成功但模型清单加载失败时可提示重试，仍可按已确认规则使用默认模型进入。
- Q10 已明确取代 ADR 0007“保存后用户刷新才生效”的旧要求；实现需要满足新的保存并应用成功／失败契约，不能仅凭当前界面已调用刷新就认定完成。
- 一个 Host 同时绑定一个工作区，更换工作区对其所有浏览器页面生效；旧页面在重载前停止操作，旧工作区请求和草稿不能提交到新工作区。这是单工作区约束下的实现要求，不引入按浏览器分别绑定的能力。

## 第二轮已确认决定

- Q7：首次预选 Codex；模型显示“使用默认模型”，默认值由 FOCUS 发布版本维护，无需联网才能确定。Codex 与 DeepSeek 分别记住用户明确选过的模型，切换回来恢复选择，同一时间只启用一个后端。
- Q8：首次连接检查使用默认模型，成功后加载真实模型清单；改选其他模型不自动再次推理，可以主动重检。界面区分“后端连接通过”和“当前模型已验证”；模型清单加载失败可以重试，也可以默认进入。
- Q9：连接检查或首次使用 AI 功能时，按需准备所选后端缺失的依赖，优先复用本机安装。跳过检查进入不触发安装；Codex 未登录时提供主动登录入口。取代旧的首次同时准备两套依赖要求。
- Q10：设置统一使用“保存并应用”；空闲时一次完成，运行任务期间禁止变更。失败时保留原生效配置并给出原因，编辑字段本身不生效；取代旧的保存后另行刷新要求。
- Q11：退出 FOCUS 后复制整个工作区目录即可备份，恢复后使用“导入工作区”原地打开。提供操作说明并实际验收全部用户资产及后续业务恢复；本期不增加备份按钮、压缩包导出、增量备份或备份管理页面。
- Q12 后续修订：用户取消独立 Windows 发行包。沿用现有项目启动与基础 Python／Node 环境，不要求解压运行、捆绑基础环境、安装器或发行产物验收；统一提示“项目目录的 `.env`”。数据与程序目录独立、资源不依赖启动工作目录、停机复制恢复的要求保留。

后端决定及其对旧路线的替代范围见 [ADR 0021](../adr/0021-simple-backend-setup-and-apply.md)。用户授权自行判断并尽量减少票数，采用三条完整交付路径；各票保留原有功能验收，不单独建立发行包或验收票。

## 交付流程

使用 `grill-with-docs` 收敛产品需求，再以 `to-spec` 与 `to-tickets` 生成正式规格和实施票。规格位于 [spec](../../.scratch/focus-workspace-portability/spec.md)，三张票及依赖见 [实施索引](../../.scratch/focus-workspace-portability/README.md)，均为 ready-for-agent。原十票草案由此替代。

三张票依次交付：完整工作区与安全接管 → 首次选择／后续换库／复制恢复 → 简洁 Backend 初始化与设置。确定性、进程、Host、浏览器及真实 Backend 验收并入对应票，最后一票包含全流程串联验证。当前只发布文档，不修改产品代码、不移动真实用户数据。
