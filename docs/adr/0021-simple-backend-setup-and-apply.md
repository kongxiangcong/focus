# 用可跳过的首次配置和保存并应用降低 Backend 配置负担

2026-10-06 Q7–Q10 确认：初始化预选 Codex，模型显示“使用默认模型”，FOCUS 发布版本提供无需联网即可确定的默认值；每个 Backend 独立记住显式模型选择，但同一 Host 只有一个当前生效 Backend。首次初始化和后续设置共用同一配置语义，用户可以跳过连接检查、模型选择或失败检查后直接进入，检查本身不启用配置。

首次检查以默认模型执行最小推理，成功后加载该 Backend 实际返回的模型清单；清单不是所有模型推理成功的证明。改选模型不自动再请求模型，可主动检查当前选择；清单加载失败时保留重试与默认使用路径。检查状态与配置身份绑定，不能将旧模型成功结果标为新选择已验证，也不静默改用其他 Backend。

本决定取代 ADR 0007 及 Stage 6B 的“首次同时安装两套依赖”：点击检查或首次调用 AI 时，仅准备所选 Backend 缺失的依赖，优先复用本机安装；跳过初始化检查不安装依赖、不登录、不发模型请求。Codex 继续复用用户已有登录，未登录时由用户主动授权，程序不读取其他原生聊天作为 FOCUS 讨论。

本决定同时取代 ADR 0007 及 Stage 6B 的“保存后手动刷新生效”：用户在空闲时点击“保存并应用”一次完成变更，运行中的任务禁止配置切换。字段编辑与连接检查不改变当前生效配置；应用失败保留原生效配置并明确失败，不能在之后重启时悄悄启用一次失败变更。共享 FOCUS 讨论、阅读位置和业务资产保持不变，各浏览器页面同步成功应用的结果。

凭据、Runtime 路径和用户配置仍在工作区外；`.env` 用于密钥等环境配置，工作台自动保存路径和选项。Backend 协议、认证及错误转换留在适配器，Core／Application 继续独占业务状态，既有取消、幂等及迟到提交拒绝约束不变。
