# 用可跳过的首次配置和保存并应用降低 Backend 配置负担

## 2026-11-20 修订

首次启动允许直接进入知识库。扫描只发现可执行路径：一个候选可预选，多个列出供选，零个提供外部安装指引与重新检测入口。扫描不启动 CLI 或发模型请求。取消默认预选 Codex 和应用内自动安装。首次使用 AI 前须由用户确认 Backend；已有有效配置继续生效。

新配置在成为当前 Backend 前必须通过配置检测，具备调用 `focus(action="read_range")` 的能力；纯文本 CLI 在配置阶段被拦截。用户可以跳过 AI 配置进入知识库。检查本身不激活配置，空闲时保存并应用；失败保留原生效配置。下列历史条款中关于默认预选、自动安装及可跳过检查使用 AI 的部分由本修订取代。

每次探针创建独立临时来源，仅开放只读动作 `read_range`，随机标记只通过本次 `focus(action="read_range")` 返回。Host 同时观察到工具调用成功和最终回复带回正确标记才判定通过。探针不访问用户知识库；以一次工具往返替换 `FOCUS_OK`，界面只显示一个检测结果。

通过回执绑定 `(backend_id, resolved_binary_path, resolved_model, command_args)`，使用实际解析的路径、模型和有序参数。点击「保存并应用」时复用匹配的通过回执，否则先检测，失败保留原生效配置。旧文本探针记录自然视为未验证，无专门迁移；下次使用 AI 或保存并应用时补测。

启动优先级为 CLI 参数 > 环境变量 > 已保存配置。显式选择即本次确认，仅对当前 Host 进程生效，跨工作区沿用。指定 Backend 检测失败时允许进入知识库，显示该 Backend 的失败原因，禁止静默回退。仅设置页主动「保存并应用」才改写 `settings.json`。

普通「检测」只验证候选配置。「保存并应用」在检测开始前取得 Host 独占切换权，持有至应用完成或失败。已有前台任务时拒绝切换；仅有后台预生成摘要时取消预生成，并拒收旧摘要的迟到结果。切换期间允许浏览知识库，新 AI 任务及第二次应用返回「正在应用 Backend，请稍后重试」。

DeepSeek 保留 Backend ID `deepseek` 和原模型偏好，标准 Manifest 启动 `dsh --profile acp`。迁移时重新发现 `dsh`，不沿用旧 SDK 专用路径。缺失时提供安装指引和指定路径入口，首次使用前按新规则检测。

默认 Codex 的 Manifest 声明 `authMode: "interactive-oauth"`，由 `codex-app-server` 驱动负责发起和取消登录。设置页按能力显示主动登录按钮；使用外部 CLI 登录的 Backend 显示各自的登录指引。

Host 启动时扫描一次 Manifest，设置页可手动「重新扫描」。扫描仅读取配置并发现可执行路径，不启动 CLI 或文件监听线程。格式错误和 ID 冲突按文件名列出原因，其他条目照常使用。在途任务和当前生效 Backend 不因扫描结果而改变。

设置文件、HTTP API、前端契约沿用 `backend` / `backends`，ID 为开放字符串。启动参数统一为 `--backend`、`--backend-bin`、`--backends-dir`。

用户 Manifest 默认从实际设置文件所在目录的 `backends/` 子目录加载，显式 `--backends-dir` 优先。Windows 默认目录为 `%LOCALAPPDATA%/FOCUS/backends/`，使用 `FOCUS_SETTINGS_FILE` 时跟随该文件位置。

沿用已保存的 `credentialFile` 路径。Manifest 只声明所需环境变量名；启动子进程时按声明从指定文件读取并注入。文件缺失或缺少所需键时提示修正路径或改用外部 CLI 认证。密钥值不写入设置、Manifest 或检测回执，服务层按相同规则处理各 Backend。

首次使用未验证配置时，界面显示「正在检测 Backend」。仅向候选 Backend 发送临时来源探针；通过后自动执行本次请求，无需重新发送。失败时保留用户输入并显示原因，用户文章和问题均不发送。

首版内置 Backend ID 固定为 `codex`、`deepseek`、`agy`、`cursor`。Claude Code 与 `codex-acp` 通过用户自定义 Manifest 注册。验收报告逐项标注真机实测状态。

以下历史条款中的首次默认模型探测及跳过失败检查后使用 AI 的行为一并取代。

## 原决定（2026-10-06）

2026-10-06 Q7–Q10 确认：初始化预选 Codex，模型显示“使用默认模型”，FOCUS 发布版本提供无需联网即可确定的默认值；每个 Backend 独立记住显式模型选择，但同一 Host 只有一个当前生效 Backend。首次初始化和后续设置共用同一配置语义，用户可以跳过连接检查、模型选择或失败检查后直接进入，检查本身不启用配置。

首次检查以默认模型执行最小推理，成功后加载该 Backend 实际返回的模型清单；清单不是所有模型推理成功的证明。改选模型不自动再请求模型，可主动检查当前选择；清单加载失败时保留重试与默认使用路径。检查状态与配置身份绑定，不能将旧模型成功结果标为新选择已验证，也不静默改用其他 Backend。

本决定取代 ADR 0007 及 Stage 6B 的“首次同时安装两套依赖”：点击检查或首次调用 AI 时，仅准备所选 Backend 缺失的依赖，优先复用本机安装；跳过初始化检查不安装依赖、不登录、不发模型请求。Codex 继续复用用户已有登录，未登录时由用户主动授权，程序不读取其他原生聊天作为 FOCUS 讨论。

本决定同时取代 ADR 0007 及 Stage 6B 的“保存后手动刷新生效”：用户在空闲时点击“保存并应用”一次完成变更，运行中的任务禁止配置切换。字段编辑与连接检查不改变当前生效配置；应用失败保留原生效配置并明确失败，不能在之后重启时悄悄启用一次失败变更。共享 FOCUS 讨论、阅读位置和业务资产保持不变，各浏览器页面同步成功应用的结果。

凭据、Runtime 路径和用户配置仍在工作区外；`.env` 用于密钥等环境配置，工作台自动保存路径和选项。Backend 协议、认证及错误转换留在适配器，Core／Application 继续独占业务状态，既有取消、幂等及迟到提交拒绝约束不变。
