# 将完整用户数据归属工作区，并在首次进入时选择

2026-10-06 用户接受渐进的数据独立方案：一个 FOCUS Workspace 包含 Knowledge Base、FOCUS Discussions 和必要业务恢复信息；工作台安装、机器配置和 Runtime 原生状态位于其外。此决定修订 ADR 0006 中将完整 FOCUS 可见讨论作为宿主私有数据保存的归属，保留原生 Runtime 会话与执行日志由对应适配器管理的原则；Core／Application 继续是唯一业务权威，本期不实施完整多宿主工程。

没有已保存工作区路径时，工作台先显示初始化界面，由用户原地导入已有工作区或选择父目录新建独立工作区；新建目录默认名为 `knowledge-base`，可以修改。成功打开后保存本机选择，后续正常启动直接进入；设置中允许在无运行任务时更换工作区。工作区身份独立于目录位置；兼容检查、停机备份恢复和受控写入者接管服务于新格式后续产生的数据。

用户明确不考虑现有 FOCUS 用户与记录：本轮不实现当前或更早布局的用户数据转换、自动发现或升级接入。现有 FOCUS 阅读数据及其关联 Host 状态不构成兼容约束，允许在实施时清理；这不扩大为删除源码、工程文档、凭据或个人 Runtime 状态。此决定扩展 ADR 0017 的重新开始范围；最终规格记录新格式首次发布后的兼容策略。

初始化新增一次后端选择，作为 ADR 0007“后端只在设置中选择”的首次进入例外。连接检查与模型手选均可跳过，检查失败也可进入，保留已有内容浏览能力并在需要模型时报告未配置状态。工作台自动保存工作区路径、后端和模型选择；项目 `.env` 保存密钥等环境配置，Codex 沿用自身登录。后续设置的生效时机和依赖准备策略由 ADR 0021 修订。

Q11 确认通过退出后的完整目录复制备份与恢复，不增加备份管理 UI。Q12 后续由用户修订为不交付独立 Windows 发行包，沿用现有项目启动和本机基础环境；只整理数据独立与必要资源定位，不为此强制重排全部模块或引入打包兼容层。项目更新、移动不改变工作区身份及已保存位置；运行环境按既有部署方式准备，不承诺虚拟环境目录本身可直接移动。AI Runtime 依赖仍按 ADR 0021 按需准备，配置提示统一为项目目录的 `.env`。
