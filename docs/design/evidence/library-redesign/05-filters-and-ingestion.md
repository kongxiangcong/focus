# Step 5: Continue reading, filters, ingestion and empty states

The Continue Reading strip uses only the current `ReadingWindow` source and `navigationCurrent ?? current`. It is limited to the all-Topic, unsearched, all-status view and the shared `reading` phase. Missing or mismatched source/chunk data, missing section text, or invalid index/total suppress the strip instead of inventing a position. Its actions reuse source inspection and the existing `enterReading` guards.

Five status filters use the existing pure status model. Counts are computed after Topic and title search, before status filtering; zero-count buttons are disabled unless selected. All Topic ordering paths share the status-filter guard through `sortingDisabledReason`.

`IngestionRows` projects the same `taskInbox` and `taskBatches` as the existing task frame, without any new requests or polling. Registered Source IDs and completed/deleted items are excluded. Real Topic ID or normalized target title controls Topic scope; Unfiled is presentation-only and means no requested Topic. Percentage updates are outside the status live region. Safe Inbox continuation and batch item retry reuse the existing wrappers, request identities and busy guards. Risky resubmission stays exclusively in the task frame. Each row can open that frame.

`LibraryEmpty` distinguishes source-list connection failure, empty library, unmatched search, unmatched status filter and empty Topic. A source-specific failure flag is set on `listSources` failed results or thrown/rejected calls, not on unrelated loading errors. Previously loaded sources remain visible when a refresh fails.

File drag displays a full-page drop overlay instead of an outline. Drop and the existing Upload button open the same upload dialog and default its editable Topic field to the current real Topic title. Unfiled never becomes a Host Topic argument. The upload browser test adds a desktop-sidebar Topic selection/default assertion, scoped within the existing upload dialog.

No contracts, Host, Core, Python, prototypes, specifications, dependencies or persistence formats changed. Existing task actions, confirmation dialogs and risky ingestion decisions remain intact. Existing tests migrate only changed empty-state text and task-frame locators where shadow rows now duplicate visible information; hidden task details remain asserted, with a new assertion that the shadow itself is visible. Screenshots were explicitly waived.
